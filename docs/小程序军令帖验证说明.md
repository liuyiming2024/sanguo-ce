# 小程序军令帖验证说明（后台开发用 · 白话 · 不进游戏）

> 本文是 `miniprogram/` 的后台全本：链路、逐文件台账、编解码口径、合规清单、成本与边界。
> **游戏内一个字都不出现**；界面侧只有 `miniprogram/README.md` 给人看的最小说明。
> 权属与证据链见 `docs/创作决策日志.md`，资料总目见 `docs/建安五年官渡舆图史料汇总.md` §16。

## 一、这份东西是什么，不是什么

| 是 | 不是 |
| --- | --- |
| 一个能导入微信开发者工具的最小原型，验证「军令帖能不能跨端逐字传」 | 发布版、提审版、上架版 |
| 网页版 `exportTicket()` 产出的 base64url 口令的**接收、校验、复制、本机留存** | 游戏客户端、Web 版的第二端 |
| 零 `wx.request` / 零云开发 / 零位图 / 零策略层的纯文本链路 | 实时同步、匹配、防作弊、常驻房间 |
| 一次工程验证，回答「微信关系链能不能补上 play-by-email 的手动交换」 | 对小程序备案 / 游戏类目资质的任何承诺 |

一句话：**它验证的是分发链路，不是算力，也不是玩法。** 早先聊过「小程序真正能蹭的不是服务器，是关系链与分发」——这份就是把那句话落成一个能跑的最小物。

## 二、链路（前后两端各自做什么）

```
网页版 一旬推进 → 系统页「导出军令帖」
      → encodeTicket({ v, game, version, date, hash, save, logTail })  [src/sync.js]
      → 一段 base64url 口令（几千字符）
      ↓ 复制 → 微信会话粘贴
小程序 pages/index
      → 读出剪贴板 / 手工粘贴
      → decodeTicket → inspectTicket（只校字段，不重放）
      → 显示：军历 / 刊本 / 图幅 / 旬次 / 指纹 / 命令尾条数 / 字符数
      → 复制转发，或存本机最近 3 帖
      ↓ 对方
对方粘进本页校验，或粘回网页版「导入」→ loadGame() → 接续一旬
```

**为什么分享卡片不带整段口令**：`onShareAppMessage` 的 `path` query 有长度限制，而 `save` 里带城池、资源、命令日志尾，整段塞进去会被截断、解不开。所以整帖走剪贴板。

**短号中转已接（Web 传帖台，非小程序侧）**：`src/ticket-store.js` 把整帖存进一张表、换回六位短号；`bridge.html` 是独立传帖台，负责发帖换号与凭号取帖。短号足够短，现在分享卡片带 `?sid=K7M2QP`，点开能看到短号，近帖留存也记它。**但本页不联网、不兑换**：小程序要访问外部服务得配 request 合法域名，第三方项目域名无法由本主体备案，所以对方拿到短号后仍要到传帖台换整帖，再粘回网页版「导入」。也就是说「点卡片直接接一局」仍未闭环，只是从「一句提示」推进到「带取件码」。完整口径见 `docs/军令帖短号中转说明.md`。

## 三、编解码口径（最容易出错的一处）

`src/sync.js` 的 `encodeTicket` 在浏览器走 `TextEncoder → btoa`，在 Node 走 `Buffer.from(...).toString('base64url')`。**小程序 JS 运行时两者都没有**（无 `TextEncoder`、无 `Buffer`、无 `btoa/atob`、无 `wx.base64ToArrayBuffer` 的等价全局），所以 `miniprogram/utils/ticket.js` 自己实现：

| 步骤 | 做法 | 易错点 |
| --- | --- | --- |
| UTF-8 | 手写逐 codePoint，显式合并 UTF-16 代理对 | 只处理 BMP 会把 `𠀀` 这类增补平面字符编错；军令帖里有中文，但测试仍覆盖 astral 字符 |
| base64 | 标准 64 字符表，3 字节 → 4 字符，尾部补 `=` | 不能漏最后一组的 `((b&15)<<2)\|(c>>6)` |
| base64url | `+→-`、`/→_`，去掉尾部 `=` | 与 Node `base64url` 完全一致，不重新 padding 也解得出 |
| 解码 | 逐字符查表、按 6 bit 累积、遇 `=` 停 | 非法字符要抛错，不能静默吞 |
| UTF-8 解码 | 手写 1/2/3/4 字节分支，>0xFFFF 拆回代理对 | 不能用 `decodeURIComponent(escape(...))` 赌宿主支持 |

**一致性怎么验**：`tests/miniprogram.test.mjs` 用 Node 同时 `import` 两端，对五组样本（ASCII、中文、韩/日/拉丁混排、emoji 与 `𠀀𪜀` 增补平面、真实军令帖形状）断言：

1. `mpEncode(obj) === webEncode(obj)`（逐字一致）；
2. `mpDecode(webEncode(obj))` 深等于 `obj`；
3. `webDecode(mpEncode(obj))` 深等于 `obj`。

这条比「看起来能解」硬得多：**只要小程序端和网页端有一个字节不一致，跨端传帖就是废品。** 主工程 `src/sync.js` 一行没改，避免为了验证去动已上线的存档口令格式。

## 六、算力与成本口径（回答「为什么不做实时」）

| 形态 | 走什么 | 百房/月量级 | 与本项目匹配度 |
| --- | --- | --- | --- |
| 异步军令帖（现有） | 本地编解码 + 剪贴板 / 云函数可选 | 约 4 元/月，免费额度基本全覆盖 | **完全匹配**：按旬推进、确定性重放、命令日志 + 状态指纹白送一致性 |
| 云托管常驻 WebSocket 实时 | 常驻容器、广播状态差、抗抖动 | 约 600 元/月起（100 房每天活跃 1 小时），24 小时不关流量单项约 8300 元/月 | **不匹配**：玩法不是即时对抗；单连接 128KB/s 上限扛不住 15552 格全量；99% 时间没人在线仍要养一台永不关机的裁判 |
| 云函数逐上行触发帧同步 | 每条消息一次调用 | 单房间 40 次/s ≈ 1.04 亿次/月，调用费约 5184 元/月/房 | **禁止**：一个实例同时只处理一条连接，会拉起海量实例 |

**翻案结论**（沿用前几轮口径）：实时同步技术上能做、个人主体也能开通云开发/云托管/建 WebSocket 房间；个人主体卡的是虚拟支付、版号、经营性服务，跟算力和实时同步无关。不做的理由从来不是「做不了」，而是「为一套按旬推进的确定性重放游戏多养一台裁判，还要把玩法改成即时制」。

云开发的官方名字与计量对照（`CloudBase` 云函数 / 云数据库 / 云存储、资源点、GBs、QPS、`callContainer` / `connectContainer` 私有链路）见 `docs/创作决策日志.md` 与 `docs/建安五年官渡舆图史料汇总.md` §16，本文不重复。

## 十、小程序适配（P1 / P2 / P3 / P5）

按研发清单「小程序适配的最小动作」落地。资质、软著、收益那摊一句没碰。

### 10.1 先纠一个清单里的判断

清单写「P1 抽 `src/platform/` 薄适配层：逻辑层 import 它，不再直接碰任何宿主 API」，并列出九个纯逻辑模块。核完发现：**这九个模块本来就是纯的**，`campaign / pathfind / terrain / siege / story / persist / formation / direction / condition` 里没有一处宿主调用，注释里「不引用 DOM / canvas / localStorage」是真的。

真正碰宿主的只有两个文件：

| 文件 | 旧口径 | 收口后 |
| --- | --- | --- |
| `src/persist.js` | `localStorage.setItem/getItem/removeItem` ×3、`Date.now()` ×1 | `storage()` / `now()` |
| `src/save-slots.js` | `localStorage` ×3（经 `safeGet/safeSet/safeDel`）、`Date.now()` ×2 | 同上 |

其余命中 `Math.random` 的多数是「无 Math.random」的注释宣言；`src/ticket-store.js` 那处是传帖台短号的回退随机源，本来就可注入 `rng`，不在这轮动。所以 P1 的实际改动面是 **2 个文件 + 新建 5 个平台文件**，不是「逻辑层全面改 import」——引擎原样搬这条比清单预想的还干净。

### 10.2 四个适配点

`src/platform/` 五个文件，零构建链、零 Promise（storage / now 全同步）：

| 文件 | 暴露 | 浏览器 | 小程序 | Node |
| --- | --- | --- | --- | --- |
| `storage.js` | `getItem / setItem / removeItem` | `browserDriver()` | `wxStorageDriver(wx)`，把「拿不到返回 `''`」归一成 `null` | `memoryDriver()` |
| `input.js` | `normalizePointer(e)` / `midpoint(a,b)` | `clientX/clientY` | `touches[0]` / `changedTouches[0]` / `detail` 归一 | 纯函数 |
| `canvas.js` | `browserCanvas()` / `wxCanvas()` | `querySelector().getContext('2d')` | `createSelectorQuery().fields({node,size})` + dpr | 返回 null 降级 |
| `index.js` | `configurePlatform / resetPlatform / detectPlatform / storage / now / randomBytes` | 自动探测 | `App.onLaunch` 注入 | 内存驱动 + 可注入固定时钟 |

`canvas.js` 这轮**只给接口**，主工程渲染层一行没改——「皮必须重写，但重写的是皮，不是引擎」，引擎层压根不该知道画布从哪来。

`now()` 只用于存档元数据与短号过期，**不进 `stateFingerprint`**；`randomBytes()` 默认 `Math.random` 兜底，策略 / 战斗 / 重放一律走 `src/rng.js` 的 `createRng`，不经过这里。

### 10.3 镜像：怎么把逻辑层「一行不改」搬过去

小程序 `miniprogramRoot: "./"` 是 `miniprogram/` 目录本身，仓库根的 `src/` 不在打包范围内。两条路里没选「把 miniprogramRoot 指到仓库根」——那会把 `docs/` `demos/` `assets/` 全打进包，2MB 主包立刻爆。

选的是 `scripts/sync-miniprogram.mjs`：

- 从 `campaign / persist / save-slots / outcome / platform/index / version` 六个入口出发，递归解析 ESM 相对 `import`，自动收出 **23 个纯逻辑 `.js`** 的闭包；
- 原字节复制到 `miniprogram/logic/src/`，**目录结构保持，所以 import 路径一个字都不用改**（`campaign.js` 里的 `./map-data.js` 复制后仍是同级）；
- `config/campaign.json` 包成 `logic/config/campaign.js` 的 ESM 模块（小程序不能直接 import `.json`），并按主工程 `boot()` 同一口径注入 `CAMPAIGN.meta.version = VERSION`，全库仍只有一个版本数字；
- 写 `logic/MANIFEST.json`：每个文件的源路径 + sha256 + 配置 hash；
- `--check` 只校验不写，`scripts/check-map.mjs` 每次自检都调它，**镜像与源一旦分叉就红灯**。

护栏里的 `FORBIDDEN` 集合写死了渲染 / 装配 / 结算层（`main.js` / `map-render.js` / `atlas.js` / `ui-shell.js` / `battle-session.js` / `siege-combat.js` …），闭包一旦撞进去直接抛错——防止哪天逻辑层不小心 import 了宿主，把皮悄悄带进引擎。

改了 `src/` 或 `config/campaign.json` 后跑一次 `npm run sync:mp` 即可，不用装任何依赖。

### 10.4 最小可玩切片（P2 / P3）

`miniprogram/pages/slice/`，从传帖台首页「打开最小可玩切片」进去。只验三件事：

1. **冷启动建局** —— 镜像 `createCampaign()` + 开局周转粮 600 + `collectResources({apply:false})`；
2. **推一旬** —— 镜像 `advanceTurn()`，把返回事件翻成文言战报文本（占地 / 屯田 / 遭围 / 城破 / 却敌 / 敌方下令 / 军粮不继）；
3. **本机存档往返** —— `onHide` 拍快照，`onShow` 无渲染恢复并比对 `hashState`。

**零 PNG、零 Canvas、零地图渲染、零结算层、零外部请求。** 页面 JS 只做注入与 `setData`，局面逻辑全在 `miniprogram/utils/slice-core.js`——这个模块不调用 `wx / Page / App / DOM`，所以端侧烟测能在 Node 里直接 import 它整条跑，不用 mock 小程序运行时。

## 十二、画布链路真接上 + 压缩分包方案（本轮）

上一刀收口列了两个方向：① 把切片页接上 `wxCanvas` 用绘制指令画格网；② 定一个压缩方案后真声明 `subpackages`。这轮两件都往前推了，但**都没越界替使用者做真机决策**。

### 12.1 为什么另开一页，而不是改切片页

§十 与 §十一 把「切片页零 PNG / 零 Canvas」写成了回归基线，`tests/miniprogram.test.mjs`、`tests/mp-bundle.test.mjs` 都在守。若把 `<canvas>` 塞进切片页，等于亲手拆掉自己刚立的基线。

所以新建 **`miniprogram/pages/canvas/`**，与切片页是两条独立路径：

| | 色块页 `pages/slice/` | 画布页 `pages/canvas/` |
| --- | --- | --- |
| 皮 | WXML `<view>` 色块 | `<canvas type="2d">` + `wxCanvas()` 拿节点 |
| 数据 | `miniMapView(state)` | `miniMapOps(state)` → `applyDrawOps(ctx, …)` |
| 位图 | 零 | 零 |
| 真机依赖 | 无 | canvas 2d 节点、DPR、基础库 |
| 失败时 | 本来就纯文本 | `_fail()` 如实报错 + 留一条回色块页的路 |

**数据层一个字没改**：`miniMapOps()` 产出的归一化 `fillRect`/`circle` 指令两边共用，浏览器端把同一份指令喂给 2d ctx 也行。这就是「皮必须重写，但重写的是皮，不是引擎」第一次真正落到代码上——上一轮 `canvas.js` 只是接口，这轮它被消费了。

### 12.2 `applyDrawOps(ctx, ops, width, height, { dpr, clear })`

加在 `src/platform/canvas.js`，**纯函数**：不引用 `document` / `window` / `wx` / `Path2D` / `Image` / `Math.random` / `Date.now`，只调用传入的 duck-typed ctx 方法。于是 Node 里用「记录型假 ctx」就能逐条断言调用序列，真机上把 `wxCanvas()` 拿到的真 ctx 传进来即可。

- 坐标 0..1 × 画布宽高 × dpr；`circle` 的半径按画布短边还原，W≠H 时仍是正圆
- `clearRect` 可关、未知 type 静默跳过、非法宽高 / 空 ctx 返回 0，不抛异常
- 另加 `hostDpr(wx)`：新 `getWindowInfo()` 优先 → 旧 `getSystemInfoSync()` 回落 → 异常兜底 2

`wxCanvas('#mini', wx, {dpr})` 仍按 §十.2 的契约：异步 `createSelectorQuery().fields({node,size})`，把 `node.width/height` 按 dpr 放大，返回 `{node, ctx, width, height, dpr}`。画布页在 `onReady()` 里初始化（小程序 canvas 节点首次渲染后才存在），推一旬后重画，拿不到节点就降级。

`tests/mp-canvas.test.mjs` 11 条，**全部从 `miniprogram/logic/` 镜像 import**：指令数与 252 格 / 城点数对齐、每条 `fillRect` 的 x/y/w/h 与颜色逐条核对、两次调用序列逐字一致、dpr=2 只翻倍不改结构、clear/未知 type/非法宽高边界、`hostDpr` 四种宿主、函数体零宿主 API、假 wx 拿到节点且 dpr 缩放、节点不存在 `resolve(null)`、画布页消费镜像且切片页仍零 Canvas、app.json 三页与首页两个入口、分包方案护栏、镜像 MANIFEST 一致。

### 12.3 压缩方案：从「直接分包会失败」到「怎么分」

上一轮结论是「3 张 PNG sheet 各自超微信单个分包 2 MB，直接声明 `subpackages` 会失败，必须先压缩」。这轮**真跑了一次压缩**，两套工具交叉验证：

| sheet | PNG | sharp webp q=80 | 压缩率 | PIL q=80 复核 |
| --- | --- | --- | --- | --- |
| `trooper-sheet.png` | 3.46 MiB | 625,768 B | 17.3% | 0.60 MiB |
| `trooper-walk-sheet.png` | 4.90 MiB | 1,105,982 B | 21.5% | 1.05 MiB |
| `engine-sheet.png` | 4.90 MiB | 972,126 B | 18.9% | 0.93 MiB |
| `trooper-tiny-sheet.png` | 0.07 MiB | 14,054 B | 19.6% | 0.01 MiB |
| **合计** | **13.32 MiB** | **2,717,930 B = 2.59 MiB** | 19.3% | 2.59 MiB |

按语义分两组（不是贪心贴边，留足余量）：

| 分包 root | 内容 | 体积 | 微信单个分包 2 MB |
| --- | --- | --- | --- |
| `assets/units-infantry` | trooper-sheet + trooper-walk-sheet | 1,731,750 B = 1.65 MiB | ✅ |

主包约 0.2 MiB（随文档/页面增补小幅变化，精确值见 `assets-plan.json`），**主包 + 分包 ≈ 2.8 MiB**，离总上限 20 MiB 还很远。所以「压缩后分包」是成立的，上一轮那句「必须压缩」现在有了具体答案。

### 12.4 真分包仍未启用（如实）

`app.json` **没有** `subpackages` 字段。理由不是方案没算清，是三件真机前提没验：

1. 小程序端 `<image>` / canvas `Image` 对 **webp** 的解码支持依基础库与平台而异，未真机验证；
2. `src/portrait.js` 是浏览器路径，直接读 `.png`；端侧皮重写后要改读分包里的 `.webp`，这一步还没做；
3. 空 `subpackages` 指向不存在的目录会在开发者工具报错，所以更不能先声明占位。

落地的是**可一键启用的完整方案**：

| 文件 | 作用 |
| --- | --- |
| `miniprogram/assets-plan.json` | 实测数字 + 阈值 + 分包表（唯一数据来源） |
| `miniprogram/app.subpackages.example.json` | 待启用模板，本身不参与编译 |
| `scripts/mp-assets.mjs --measure` | 用 sharp 实测并刷新上面两份 |
| `scripts/mp-assets.mjs --build` | 生成 webp 到 `miniprogram/assets/`（`.gitignore` 忽略，**不进仓库**） |
| `scripts/mp-assets.mjs --check` | 护栏：每组 ≤ 2 MB、主包 ≤ 2 MB、总 ≤ 20 MB、plan 的 PNG 字节与磁盘逐一对得上、`portrait.js` 的 sheet 清单没变 |

真机时的三步：`npm run assets:build` → 把 `app.subpackages.example.json` 的 `subpackages` 数组并入 `app.json` → 皮重写时把资源路径改成 `.webp`。`--check` 被 `npm run check` 每轮调用，**不依赖 sharp**（CI 没装也绿）；`measure/build` 才用 `createRequire` 加载全局 sharp。

## 十三、可交互格网：视口 + 命中 + P1 收口（本轮）

上一刀收口列了两个方向：① 真机 `assets:build` 并启用 `subpackages`；② 把 `miniMapOps` 从 18×14 缩略推进成带视口与命中的可交互格网。**这轮只做 ②**——① 需要真机运行时验 webp 解码与端侧皮重写读 `.webp`，本仓库两路都没有，不擅自声明空分包、不假装验过。§十二.5 那张边界表原样有效。

### 13.1 三层，全在镜像逻辑层

| 层 | 函数 | 口径 |
| --- | --- | --- |
| 视口 | `miniMapSize / fullBox / clampBox / boxOf / boxZoom` | 给 `miniMapCells(state, opts)` 传 `opts.box` 看局部；**不给时输出与上一轮 18×14 全图逐字一致**（回归基线不破）。`clampBox` 保证跨度不小于 12×9 源格、左上角不越界 |
| 相机 | `panBox / zoomBox / createMiniCamera` | `zoomBox(box, factor, anchor, W, H)`：`factor > 1` 拉近，缩放前后 **anchor 指向的源格不动**（指哪缩哪）。全是纯函数，无墙钟、无随机；相机对象 `get box` 返回副本，外部改不动内部 |
| 命中 | `hitTestMiniMap / resolveMiniMapHit` | `point` 归一化 0..1 → 输出格 → 该格覆盖的源格范围 → 中心真实 tile，返回 `{sc, sr, tileIndex, owner, terrain, cityId, color, box, zoom}` |

**`resolveMiniMapHit(e, rect, state, opts)` 把主工程那套「一律 `clientX/clientY` + 实时 `rect` 补一次命中」真正落地了**：内部走 `input.js` 的 `normalizePointer(e)`，把 mouse / `touches[0]` / `changedTouches[0]` / `detail` 四种事件形状统一，再用 `rect.left/top/width/height` 归一。

这正是 P1 四个适配点里**最后一个没被消费的**：storage 早被 `persist.js` / `save-slots.js` 收口、canvas 上一轮被画布页消费、index 由 `app.js` 注入，现在 input 也被命中层接上。四个点全部有真实调用方，不再是摆着的接口。

`input.js` 同时补了多指：`normalizeTouches` / `touchDistance` / `pinchRatio`（两指距离比，>1 张开拉近、<1 捏合拉远，不足两指或距离为 0 一律返回 1 不抛异常）。`wxCanvas` 也加返回实时 `rect`（`fields({node,size,rect})`），命中换算才有 `left/top`；假 wx 没给就按 0 兜底，旧测试不破。

### 13.2 两条皮共用同一份数据

| | 色块页 `pages/slice/` | 画布页 `pages/canvas/` |
| --- | --- | --- |
| 交互 | 点 WXML 色块（`data-i` + `bindtap`）查格；按钮放大/缩小/复位 | 单指拖拽平移、双指捏合缩放、抬手点击查格；另有三个按钮 |
| 事件 | `data-i` → 归一化点 → `miniHit()` | touch 三事件 → `normalizeTouches` / `pinchRatio` → `camera.pan/zoom` → `miniResolveHit()` |
| Canvas | **零**（基线保持） | `<canvas type="2d">` |
| 数据 | `miniMapView(state, cam.opts())` | `miniMapOps(state, cam.opts())` → `applyDrawOps` |
| 位图 | 零 | 零 |

放大后同一点命中的源格会变（`sc/sr` 不同），说明视口真的接进了降采样而不是只换了个显示倍率。推旬、读档、切后台回来时相机复位，格网随战线重算。
