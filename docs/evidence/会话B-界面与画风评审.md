问答分享
一句话结论：**氛围和完成度是 9 分，工程严谨度大概 7 分**——这是那种"一个人闷头把整个 SLG 的皮都画完了"的样式表，审美、层级、响应式都有章法，但已经攒下几处**会真在屏幕上出事**的隐患，而且都不是审美问题，是 CSS 机制问题。

---

## 先说写得好的

- **变量体系是语义化的**，不是 `--color1/2/3`：`--ink / --paper / --gold / --red / --line` 一套读下来就知道色板逻辑，后面换肤有支点。
- **z-index 有规划**：1(map) → 15(log) → 20(topBar) → 30(bottomBar) → 34(sheet) → 60(screen) → 80/82/100/140(overlay/menu/toast)，能看出是排过座的，不是随手 `9999`。
- **装饰层的思路对**：`body::before/::after` + `pointer-events:none`，暗角、扫描线、金线全用渐变生成，零位图；`[hidden]{display:none!important}`、`tabular-nums`、`touch-action:none`、安全区、scrollbar 定制这些细节都补了。
- **状态覆盖得全**：`hover / aria-pressed / :disabled / .locked / .empty / .dragging / .show`，移动端把 `.sheetCard` 改成底部升起 + grabber 且保留原 id 给 JS，说明是边写边想着真实交互的，不是静态稿。

---

## 但有几处是会真出问题的

**① 装饰层压在所有弹窗之上（最该先修）**

`body::before/::after` 是 `z-index:200/201`，而 `#screen` 60、`#battleOverlay` 80、`#helpPanel` 82、`#mainMenu` 100、`#toast` 140。它们和 body 伪元素同处根层叠上下文，所以**暗角、扫描线会盖在开局菜单、全屏子页和 toast 上**——菜单四角被压暗 46%，顶部还被那两条"金线"切一道。`pointer-events:none` 只保证不挡点击，不保证不挡视觉。

```css
/* 暗角只该压地图，不该压 UI */
body::before{z-index:2}
body::after{z-index:3}
```
`#map` 是 1，`#log` 是 15，改成 2/3 后装饰恰好夹在中间，一行就解决。

**② `body::after` 的渐变方向写反了，金线其实只有两个点**

```css
linear-gradient(90deg,var(--goldDim) 0 1px,transparent 1px) 8px 8px/calc(100% - 16px) 1px
```
`90deg` 是**横向**渐变，`goldDim 0 1px` 意味着只有最左 1px 上色、其余全透明；再配上 `height:1px` 的背景尺寸，最终渲染出来是上下各一个 1×1 的金点，不是贯通的边框线。对照你 `#topBar::before` 的写法就知道本意是什么：

```css
linear-gradient(90deg,transparent,var(--gold) 12%,var(--gold2) 50%,var(--gold) 88%,transparent)
```
顺带一提，`#topBar` / `#bottomBar` / `.cityGround` 里的 `repeating-linear-gradient(0deg,...)` 和 `90deg` 网格线都是对的，只有这一处翻车。

**③ `env()` 没写降级，老浏览器整条声明作废**

`bottom:calc(70px + env(safe-area-inset-bottom))` 在不支持 `env()` 的引擎里，整个 `calc()` 解析失败 → `bottom` 变 `auto`，`#mapTools` 会飘走；`padding:0 8px env(...)` 同理，连那 8px 横向内边距一起丢。标准双写：

```css
#mapTools{bottom:70px;bottom:calc(70px + env(safe-area-inset-bottom))}
#bottomBar{padding:0 8px;padding:0 8px env(safe-area-inset-bottom)}
```

**④ `.x` 没有基类，定位靠"碰巧匹配"**

`position:absolute` 只写在 `.sheetCard .x` 和 `#helpPanel .x` 里，`.x` 本身是裸的。于是 `#battleOverlay .x{top:10px;right:12px;z-index:3;...}` 如果那个按钮没同时挂 `.sheetCard`，这四个属性全部失效，关闭按钮会掉进 flex 流里跑到 canvas 上方。同理 `.scrHead::before` 是 `position:absolute` 但 `.scrHead` 没有 `position:relative`，它实际是相对 `#screen` 定位的——现在恰好贴顶所以看不出来，一改 padding 就漂。

```css
.x{position:absolute;top:8px;right:9px;cursor:pointer;/* 公共尺寸/配色 */}
.scrHead{position:relative}          /* 让 ::before 老实待在标题栏 */
.scrHead .x{position:static}         /* 标题栏里本来就该是 flex item */
```

**⑤ flex 子项的 `min-width:auto` 会让横滑失效**

`#topBar .res{flex:1;overflow-x:auto}` 少了 `min-width:0`：flex item 默认最小宽度等于内容宽度，资源一多就先把 `#topBar` 撑爆，移动端 `overflow:hidden` 直接把右侧 `.hudExtra` 的设置按钮裁掉。桌面端 `#topBar` 没 `overflow` 更会挤出屏。补 `#topBar .res{min-width:0}`、`.hudExtra{min-width:0;flex-shrink:0}` 就好。

**⑥ 矮屏上 `battleOverlay` 可能把关闭按钮裁掉**

`#battleOverlay{overflow:hidden}` 是硬裁，里面 head + `flex:1` 的 canvas + 9 格 grid + note + 按钮全塞在列 flex 里。移动端把 `.battleGrid` 从 9 列改 3 列，9 个格子就变成 3 行，高度反而涨了；`min-height:220px` 的 canvas 不肯让，667px 高的机器上底部按钮很容易被吃掉且滚不动。建议给下半部分包一层 `overflow:auto` 的容器，或把 canvas 改成 `flex:0 0 38vh`。

## 可维护性上的债

启动得很快的原型都长这样，不致命，但越往后越贵：

- **死变量**：`--ink2`、`--ink3` 定义了全篇没用；`--jade` 只出现过一次。而 `#7d211c / #79201b / #f3e7d2 / #a9d4e6 / #e9a99d / #6e7869 / #0d1210` 这些硬编码散在各处，等于换肤时色板只管住一半。
- **同一套东西写了四五遍**：绛红主按钮有 `.bigBtn`、`.startBtn`、`.cmdGroup button.primary`、`#mapTools button.primary`、`.closeBattle` 五份渐变；进度条填充有 `.progress i` / `.fac .fbar i` / `.dimRow .dbar i` 三份；关闭按钮四份。抽 `.btn-primary / .btn-ghost / .barFill / .x` 能砍掉近百行。
- **权重被 id 抬高了**：`#infoBody .row b` 这类是 (1,1,1)，以后想覆盖只能继续叠 id 或上 `!important`。更明显的信号是 `#infoCard,#cityPanel,#orderList{right:14px;top:64px;width:270px}` 把 `.sheetCard` 的属性原样抄了一遍，移动端媒体查询里又抄一遍——这基本说明 HTML 上类没统一挂。建议 **id 只留给 JS 当钩子，样式一律走类**。
- `#battleOverlay{transform:none;max-height:none}` 是防御性残留，看着像是从某个通用弹层类改过来没清干净。

## 体验与可访问性补漏

对比度实测（对 `--ink:#0a0d0c`）：

| 色 | 对比度 | 判断 |
|---|---|---|
| `--dim #8f998b` | 6.60:1 | 舒服 |
| `--paper2 #c9c2ad` | 10.97:1 | 舒服 |
| `--gold #c8a86a` | 8.61:1 | 舒服 |
| `--gold2 #8d7546` | **4.43:1** | 临界，却用在 10~11px 的 `.rarity`、`.res .k` 上 |
| `.tiny #6e7869` | **4.23:1** | 低于 AA，且是 10px 字 |

再叠 `.fac.locked{opacity:.42}`，锁定项基本读不清了。这两支提亮一档就够。

其余几个小口子：全篇只有 `:hover` 没有 `:focus-visible`（你是 PC 端，键盘 Tab 会完全看不出落点）；`.hudBtn` 移动端 36px 小于 44×44 触控建议；`scrIn / sheetUp` 没有 `prefers-reduced-motion` 降级；`#toast` 缺 `aria-live="polite"`；`.fac / .card / .slot / .listRow` 都带 `cursor:pointer`，若 HTML 是 `div`，记得补 `role="button"` + `tabindex` 和键盘事件。

## 最后一个小落差

注释写的是"回纹、印玺、宣纸噪点、暗角由 CSS/SVG 生成"，但代码里**没有 SVG**，回纹其实只是 `.sheetCard::before/::after` 的 L 形直角（真正的回字纹没画），"宣纸噪点"是 1px 扫描线不是噪点。观感没受影响，属于注释比实现快了半步——哪天真要补回纹时别以为已经有了。

## 最小改动清单（按收益排序）

1. 装饰层 `z-index` 200/201 → 2/3 —— 1 行，收益最大
2. 修 `body::after` 渐变方向 —— 1 行
3. 所有 `env()` 双写降级 —— 几行
4. 抽 `.x` 基类 + `.scrHead{position:relative}` + flex  `min-width:0` —— 十几行
5. 之后再谈抽按钮/进度条、清死变量、补 `focus-visible` 和 `reduced-motion`

前四条基本都是"一行级"修补，改完这套皮的稳定性会直接跨一个台阶。整体我挺喜欢——**变量命名和移动端那套底部 sheet 的重排，比很多上线项目都讲究**；现在缺的不是审美，是收尾时把浏览器机制那几个坑踩平。
定调：**这套皮的审美是"懂克制的人做的"**，最值钱的不是画了多少纹样，而是所有颜色都往灰里收了半档——这一步就把它和满屏亮金正红的页游 UI 拉开了代差。

## 最漂亮的三笔

**① 色板全部"降饱和半档"**

`#0a0d0c` 不是纯黑，带一丝青绿气，像久置的墨；`#e9e3d1` 不是白，是放旧了的宣纸；`#c8a86a` 不是金箔，是氧化过的青铜；`#a63129` 不是正红，是干掉的朱砂。四个主色统一压过灰，整套才不刺眼。**这是全篇审美的命门**——只要把 `--gold` 换成 `#ffd700`、把 `--red` 换成 `#e60000`，立刻垮成传奇风。

**② 竖排 + 字距的递进**

`.seal` / `.mseal` / `.pseal` 的 `writing-mode:vertical-rl; text-orientation:upright`，加上 `letter-spacing` 从正文 0~2px → 标题 2~3px → 菜单 h1 12px → 武将名 10px 的梯度，是唯一真正带出"汉简印玺"气韵的地方。印玺做成 30px 小红块、内嵌一圈暗边，比画个假玉玺高级得多——**抽象对了，比具象耐看**。

**③ 线的语言统一且轻**

全篇几乎只用 1px + `.26 / .14` 透明度的金线，没有实色分隔块，没有滥用圆角（2~3px 到底），阴影全是往下压的黑、没有四处飘的发光。`.secTitle` 用「3px 红竖杠 + 一条渐隐金线」概括卷轴题头，是那种"不画卷轴却让人想到卷轴"的处理，分寸很好。

移动端把侧挂卷轴改成**底部上翻 + 10px 上圆角 + grabber**，尤其聪明：材质从"挂着的卷"变成"推上来的奏折"，物理感换了，语汇没断。比把桌面版硬缩小一档高明。

## 最可惜的三处

**① 绛红撒得太匀，反而丢了"战火"**

注释里写「绛红＝战火」，本该是稀缺的点睛。但现在印玺、所有主按钮、badge、章节红杠、`aria-pressed` 下划线、战报判定、log 左边线、关闭按钮……全在红。红一多就不再是警报和血性，退化成第二主色，**玄黑＋旧金那股权谋的冷感被稀释了**。

更狠的做法：红只留给「不可逆动作（出征/解散）」和「出血信息（战报/败报）」，其余层级全交给金的明度差去表达。少一半红，贵气会翻倍。

**② 每块都有框，等于没有留白**

顶栏一条金线、底栏一条、子页头一条、body 上下各一条、sheet 双 L 角、cityGround 内外双框、menuCard 内框、facCore 斜纹……单看每一处都精致，叠在同一屏里就变成"处处有边"。中式审美的贵气靠**空**，不靠满。建议只保「外框 + 一处角饰」，把 `scrHead::before` 和 `cityGround::before` 这类内层线撤掉，中间那块黑才有呼吸。

**③ "蚕白（礼政）"其实没出场**

`--paper` 全程只拿来写字，没有任何一块浅色纸面。结果内政、政令、任务、邮件、天下这五个"文治页"和城池、出征、布阵长得一模一样，翻页没有节奏，看久了会闷。

整套最值得补的一笔就在这儿：**给文治类页面反一张纸底**——`paper` 底、`ink` 字、一枚朱印、金线收边。一深一浅，立刻有「武 / 文」两张脸，注释里那个三色叙事才真正立住。这比再加十个角饰都管用。

## 一个会悄悄掉档的落地问题

`--serif` 首位是 `Songti SC`（仅 macOS），Windows 上大概率落到第三四位，`WenQuanYi Micro Hei` 是**黑体**不是宋体。也就是说同一份设计在 Win 上会变成黑体配 12px 字距配竖排，古意直接掉一半——这是审美落地，不是代码 bug。把 `Noto Serif CJK SC` / `Source Han Serif SC` 提前，再补个 `SimSun` 兜底（丑，但至少是宋），竖排那两笔才不白写。

顺带 `.portrait .pname` 的 38px 竖排配 `letter-spacing:10px`，在 230px 宽的框里字会散、也容易顶边，想法很好，尺度收一档更稳。

## 如果只改一处

**收红，或者给文治页加一张纸。** 前者几乎零成本、立刻更贵；后者多一点工作量，但能把"率式美学"从一句注释变成真的叙事结构。

整体定位：比常见 SLG 皮肤高一级，接近《率土之滨》早期那股「水墨＋印玺」的克制；离真正考据过的汉末质感，差的不是纹样，是**留白和纸性**。现在它有点像把好料子全铺在桌上了——料子是真不错，该收一收了。
**成了。** 收红和纸性这两笔都真落地了，而且比我预想干净——工程那几条也基本一次改对。但现在卡在最后一公里：**红是收住了，主操作跟着一起没了重量；纸是铺出来了，但它是靠 40 行白名单铺的，不是靠一套色调。**

## 改对的地方（不用再动了）

- 装饰层降到 2/3、`env()` 全部双写降级、`.x` 基类化 + `.scrHead{position:relative}`、`min-width:0`、`focus-visible`、`reduced-motion`、字体栈提前、`--gold2` 提亮到 `#a08a58`（墨底 **5.83:1**）、`.tiny` 换 `--dimDeep`（**6.23:1**）——对比度欠账全清了。
- **留白做得比我想的狠**：`sheetCard` 四角收成一处、`menuCard`/`cityGround`/`scrHead` 的内层线全撤、`facCore` 斜纹去掉、`.portrait` 的红晕换成金晕、`pname` 38px/10px 收到 32px/6px。这几处一撤，中间那块黑真的开始呼吸了。
- **红的分配完全对**：现在只剩三枚印玺、纸页朱印、`.verdict`、`.tag.red`、`.bigBtn`、`.startBtn`。正好是「不可逆动作 + 出血信息 + 品牌符号」，没有一处在乱撒。`badge` 改金底墨字是 5.83:1，可读，只是提醒感弱了——这是收红必然的代价，接受就行。
- 布阵页 `overflow-y:auto` + `flex:0 0 min(42vh,420px)` 修得对，矮屏不再硬裁。

## 收红收出来的副作用：主按钮失重

这是这版最该改的一处。`.cmdGroup button.primary` 从深红渐变换成 `--goldGrad`（`rgba(200,168,106,.20→.06)`，均值约 **.13**），而普通按钮是 **.07**、hover 是 **.18**。结果：

> 静止的主按钮，比一个被 hover 的普通按钮还暗。

`#mapTools button.primary` 同理，金色字 + 淡金渐变，和普通态只剩一条边框的差别。用户在地块面板里会找不到「执行」在哪。

红不该回来，但重量得用别的给——**墨底反金**最贴这套语汇，且不破坏收红：

```css
.cmdGroup button.primary,
#mapTools button.primary{
  background:var(--ink);              /* 不用红也有重量 */
  border-color:var(--gold);
  color:var(--gold);
  box-shadow:inset 0 0 0 1px rgba(200,168,106,.22);
}
```

## 纸页：方向满分，实现是白名单

`头部墨 + 身体纸` 的翻页节奏**立住了**，褐金标题 `#6a5227`、朱印、极淡的横纹都很到位。但那 40 行是「按当前页面清单逐条点名」，实测把原色板变量放到纸底上：

| 原变量 | 对 `#e7e0cc` 对比度 |
|---|---|
| `--gold #c8a86a` | **1.72:1** |
| `--gold2 #a08a58` | **2.54:1** |
| `--dim #8f998b` | **2.24:1** |
| `--blueTxt #a9d4e6` | **1.20:1** |

也就是说：**任何没列进白名单的组件，在纸页上等于隐形。** 而覆盖清单只点到了 25 个类，漏掉的偏偏是常见的：`.rarity` / `.stars`（星与品级，1.72:1）、`.intel`（情报条，1.20:1，整块消失）、`.fac / .facCore / .glyph / .fn / .slot / .hn / .dimRow .dv`、`.tag.red`。更典型的是 `.cityGround` 只改了 `border-color`，`background` 还是实色 `#141b16`——纸页里一旦出现设施俯视图，就是一张黑方块。半吊子覆盖比不覆盖更危险。

而且纸页自己还在串色：`.secTitle` 字是褐金 `#6a5227`，`::before` 竖杠却写 `var(--gold2)` 引回深底那支亮金，一行里三个金不同调；40 行里又新攒了 `#6b6755 / #5d5949 / #5c5b4c / #7a6033 / rgba(140,115,70,…)` 一整套没进变量表的纸色。

更稳的做法是**把纸当成一组局部色调**，让组件自动继承，而不是点名：

```css
#screen[data-tone="paper"] .scrBody{
  --paper:#20251f; --paper2:#3a3b30; --dim:#5d5949;
  --gold:#6a5227;  --gold2:#7a6033;
  --line:rgba(122,96,51,.34); --line2:rgba(122,96,51,.18);
  --goldGrad:linear-gradient(180deg,rgba(122,96,51,.18),rgba(122,96,51,.05));
  --cardBg:rgba(255,255,255,.46);
  color:var(--paper);
}
```

前提是先把 `.stat / .card / .panel / .troopCard / .cityGround` 里硬编码的 `rgba(8,12,10,.6)`、`#141b16`、深绿渐变换成 `var(--cardBg)`。换完那 40 行能砍到 10 行，以后往文治页塞任何新组件都不会穿帮，也不用在移动端再抄一遍。

**另一个确定的坑**：朱印挂在 `.scrBody::before` 上，而 `.scrBody` 是 `overflow:auto` 的滚动容器——纸的纹理不会跟着滚（背景默认 `scroll`），但**这个 absolute 伪元素会**，长战报滚到一半印就跑到上面去了。一行就能挪走：

```css
#screen[data-tone="paper"]::after{content:"政";position:absolute;bottom:34px;right:26px;
  z-index:2;pointer-events:none;/* 尺寸印色照搬 */}
```

`#screen` 本身 `position:absolute`，天然是 containing block，不用额外加 relative。

## 顺手能删的两处

`body::after` 现在那条贯通金线在 `8px 8px`，可 `#topBar` 是 `z-index:20`、背景 `.97` 不透明、从 `top:0` 盖到 50px——**这条线基本看不见**，而且 `#topBar::before` 已经有同款 2px 金线、`border-bottom` 还有一道。注释写「只留一条外框金线」，实际是「一条被压在顶栏底下、和顶栏金线重复的线」。删掉它和随之成为死变量的 `--goldDim`，正好又是留白。

同类小尾巴：`.hudExtra{flex:0 1 auto;flex-shrink:0}` 后者把前者覆盖成 `0 0 auto`，合成一行即可；`--goldDim` 是现在唯一定义未使用的变量。

## 一个连带出来的新问题

`#battleOverlay` 从 `overflow:hidden` 改成 `overflow-y:auto` 之后，`.x` 是 `position:absolute`、`.battleHead` 是普通 flex 子项——**两者现在都会跟着整页滚走**，矮屏上滚到下面就没法关了。`.sheetCard .x` 也有同样的老毛病。最一致的修法是照抄 `#screen` 的结构：滚动下移给一个 `.battleBody` 包裹层，head 和关闭按钮留在不滚的外层。

## 最值钱的其实不是颜色，是"命名与文案"

`TABS` 里 11 个单字 glyph（舆/城/将/策/阵/报/书/令/盟/势/设）、标题「先探后战，量力而行」「合纵连横」、预判「兵不血刃 / 杀敌一千」、开局「普天之下，莫非王土」、竖排名 + 印玺 + 旬历——这套**文本系统**才是古意的来源。它比任何一条金线都难写，而且已经立住了。地图那边也一样：竖排城名靠右压在城郭旁、关隘三角符 / 津渡圆点、山水注记沿折线斜排、图廓与比例尺，明确拒绝"圆圈里写个汉字"。零位图、确定性 hash 画出这些，属于有考据野心的做法。

纸/墨二分也确实建立了翻页节奏，**「天下」是整套里最漂亮的一页**：四格数值、三条势力进度、十二张城池小卡、右下朱印，疏密有致，像一页真正能读的形势图。

这一页的纸性、留白、金线收边都成立；问题不在它，在于它是**手工点名覆盖出来的**，别处没跟上。

## 三个真正拖后腿的，全都不是配色

**① 调试信息升格成了一级 UI。** 城池布阵页下方 9 格：「上次快照 / 秒」「快进步数」「累计逻辑步」「策略时刻 / 秒」；toast 写「已拍快照 @ 6.4s，策略日历继续走」，日志写「退出城池，快照 6.4s / 第 1 旬」。玩家刚被帐篷、篝火、垛口拉进许都，下一行就被拽回控制台。这是**信息编排的身份错位**——工程上最自豪的双时钟，恰恰是美术上最出戏的一块。布阵页还因此把画布压到 42vh，下面留了近 300px 纯黑。

**② 地图装饰密度压过了读图。** 官道是 8px 深底 + 4.2px 金芯，且每格对 8 个邻格各画一次 links，相邻格重复叠加，最后变成一条条**金色编织带**；加上每格一个三角山形，整幅地图像挂毯多过像舆图。实测高亮金像素占画面 **4.66%**，手机视口裁切后升到 **7.53%**。

[](@replace=media_36f00b1e342250d1)


看这张：最先被眼睛接住的是交叉的金带，不是城池、河防和关隘。另外缩略导航算出来在 `x1236–1426 / y699–842`，右下工具列占 `x1386–1430 / y384–830`，右缘整条被压住；而缩略图本身是同色系地图的缩小版、只有 1px 金框，在暗角下几乎认不出那里有个导航器。手机上更极端：工具列吃掉 1/8 屏宽，底栏只露出 6 个 Tab，地图彻底变成纹样。

**③ 全局导航自己把自己盖掉了。** `#screen` 是 `z-index:60`、`inset:0`，`#bottomBar` 是 30。实测在底部「武将」Tab 中心做命中测试，返回的是 `.scrBody`——**打开任一全屏页，11 个 Tab 立刻不可见也不可点**，只能 × 或 ‹返回 退回地图再重进。README 写「从 Tab 切页会重置导航栈」，实际体验是每次翻页都得先合上书回到封面。最伤的正是你想要的"翻页节奏"：本该像翻书，现在像开关灯。

## 收红与纸性：方向对，落地反了三处

红色像素实测：武将库、战报、布阵页 **0.00%**，菜单 0.24%，纸页 0.16–0.33%。收得比注释还彻底，但**"绛红＝战火"的语义反了**——红几乎只出现在文治页（右下朱印、天下页 12 枚势力小印、内政页六个暗红数字），武备页除「确认出征」外全无红。出征页那一抹暗红渐变 + 红左框的「兵不血刃」是全套用得最准的一笔，可惜只有这一页。红从叙事色退化成了**品牌标记 + 一个按钮**。

与之连带的是**主操作失重**：开局「新开一局」是 ghost 暗按钮、地块卷轴「进入城池布阵 →」是淡金渐变、武将详情的五边形雷达细到几乎看不见（五条金条反倒成了主角）。整局最常点的入口全平，唯一有重量的是那个不常点的红按钮。上一轮担心的那件事，实拍确认了。

纸性则只铺了一半：`cityGround` 在纸页下只改了 `border-color`，背景仍是 `#141b16` 的深墨网格，于是内政页变成**浅米纸上贴了一块黑板**，手机宽度下几乎占满纸面。

[](@replace=media_30d2c3a4555787ac)


看这张：上半是纸，中间是墨，下半又回到纸，材质不是"反了一张纸"，是"纸上挖了个洞"。另外朱印挂在 `.scrBody::before` 上，而 `.scrBody` 是滚动容器——移动端内政页可滚 **828px**，滚到 700px 时朱印已经跟着内容滚出视口，纸的底纹却不跟着滚，材质再次断层。
