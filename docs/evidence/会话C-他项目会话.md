## 🔴 三处最要命的

**1. 整个游戏跑在「每帧一次」上，没有 delta time**
`attackCd -= 1`、`speed += 1`、AI 出兵 `Math.random() < 0.005`、矿工产金 `0.010` 全按帧计。60Hz 下剑士约 1.17 秒一刀，120Hz 高刷屏直接变 0.58 秒；刷兵和产金同步翻倍，等于**屏幕刷新率决定难度和经济**。掉帧则全场慢动作。这是教科书级问题，一行 `dt` 能救一半。

**2. 矿工是个假矿工**
矿工配置 `dmg:0, range:0, baseCd:0` → 攻击冷却恒为 0，每帧都进攻击分支，把贴身目标的 `hitFlash` 每帧重置成 10，敌人**永久闪白**；到敌方基地后 `enemyHp -= 0` 但挥拳动画常驻。更根本的是产金逻辑：

```js
if (u.type === 'miner' && u.team === 0 && Math.random() < 0.010) gold += 6;
```

和位置、和中间那个画了「金矿」的圆、和挖掘动作**完全无关**。矿工站在出生点不动也照刷钱，它本质是「带矿工贴图的随机数发生器」。原版最核心的挖矿—运矿循环被跳过了。

**3. 提示闪 16 毫秒就没了**
`flashText()` 把 `#gold` 改成「金币不够」，但 `update()` 每帧末尾调 `updateUI()` 覆盖回去 → 提示存在约一帧，肉眼看不见。配套的 `updateButtons()` 只加 `.disabled` class 做置灰，**没设 `btn.disabled`**，灰了照样能点。视觉上禁用了，行为上没禁用。

## 🟠 逻辑与状态

- **雕像画在 x=74，伤害判定线却在 160**。单位走到 161 就开始扣血，离雕像视觉中心还差 87px，看着像隔空拆家。
- **AI 没有人口上限**。玩家卡 `popMax=20`，`aiSpawn()` 直接 `push`，不看金币不看人口，长局无限堆兵；且只出剑士/矛士/弓箭手三种等概率随机，巨人巫师投石兵玩家独占，升级只对玩家生效 → 难度曲线是单边塌的。
- **`resetGame()` 不重置 `upgradeData`**。重开一局金币回到 120，但上局花 80 金币买的攻/防/速等级全继承，README 只字未提。
- 默认 `gameMode='defend'` 时我方单位无目标就原地不动，而敌人持续左推；「进攻/固守」按钮**没有选中态**，新手会以为卡死了。
- `radius` 字段定义了、赋值了，全文再没被读过；`assetsReady` 也是只写不读的死变量。单位之间无碰撞，20 个人可以叠成一个像素。
- `draw()` 里 `units.sort((a,b)=>a.x-b.x)` 每帧改数组顺序，而 `update()` 靠倒序 `splice` 删人 → **物理遍历顺序被渲染顺序绑架**。且所有单位 `y` 恒为 `h*0.76`，根本没有深度，按 x 排序纯多余。
- 远程兵只在原地画一道 14 帧的弧光，没有投射物、没有飞行、没有命中延迟。

## 🟡 工程与性能

- `drawSprite()` 对受击单位设 `ctx.filter = 'brightness(1.75)'` 并 save/restore。Canvas2D 里 filter 是最贵的操作之一，移动端每帧对多个单位做，掉帧预定；其实改 `globalAlpha` 或叠一层白矩形就够了。
- 每帧 4 次 `textContent` + 7 次 `classList` + 全屏背景缩放重算，无脏检查、无缓存。`drawBackground` 的 `ir/cr/dw/dh` 只在 resize 时变，却每帧算。
- `onerror` 提示「已使用替代绘制」，但 `drawSprite` 里 `if (!img || !img.width) return` —— 素材缺失时单位**直接隐形**，文案撒谎。无重试、无超时。
- 全内联 `onclick` + `innerHTML` 字符串拼 `doUp('key','atk')`，两种事件绑定风格混用；目前数据都是常量所以没 XSS，但凡以后兵种名来自外部就是现成的洞。没有 CSP、没有模块拆分、没有构建、没有 lint、没有一行测试、没有 CI。
- 数据口径也对不上：manifest 里 webp 合计约 **127KB**，README 写「约 150KB」；manifest 还记录着 `png`/`jpg` 原始体积，但仓库里这些文件根本不存在，是幽灵字段。

## ✅ 公允地说
