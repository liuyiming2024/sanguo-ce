# 墨战机制对照与「将领真兵」设计

> **口径（用户定）：只是借鉴玩法，不引入机制。** 借的是「怎么打、怎么看」：画圈选中、
> 点目的地奔赴、实时攻防、水墨拖痕、战殁消散、技能触发的即时反馈、单局节奏。
> **不引入**：兵种合成／汉字组合、卡牌与日卡次卡养成、稀有度与战后选卡、
> 天气改数值、最后一击定归属、小兵牺牲降城防。下文凡出现这些机制描述，
> 仅作检索留痕与「为何不借鉴」的依据，一律不进代码、不进配置、不进设计。


> 本文件只汇总**公开资料里的机制描述**用于设计对照，不复制小程序的代码、图片、字体、
> 卡牌文案原文或任何素材；游戏内实现全部自撰。墨战为北京蜜獾工坊的水墨风微信／抖音
> 小游戏，与本项目无隶属关系，此处仅作玩法参照。

## 一、查到的墨战是什么

两轮联网检索（2026-11-19）交叉后，可信度较高的共同描述：

- 水墨风 2D 即时战略／塔防小游戏，微信与抖音端同名，单局 3–5 分钟，蜜獾工坊（《躺平发育》团队）出品 [1][3][6][10]。
- **画圈／下划选中士兵 → 点击位置派遣 → 布阵攻城 → 占领所有城池获胜**，失去全部城池失败 [1][3][6][11]。
- **初始城池自动产兵**，每占一城多一条产线；**城池自带防御塔**，敌兵靠近自动攻击，高等级城池防御更强 [5][10][11][20]。
- 检索中还见到技能卡牌、稀有度、连锁构筑、汉字兵种合成等体系 [1][5][15][17][20][24]。
  **按用户口径「只是借鉴玩法」，这些机制一律不引入**，此处留一条检索痕迹即可，不展开。
- 阵法（多站口径一致）：鹤翼（两翼移速 +20%）、**锋矢（阵型最前端将领获得临时霸体）**、
  **八卦（敌人随机丢失攻击目标）**、雁行（弓弩射击间隔缩短）、**车悬（近战每攻击 5 次后自动后撤休整）** [7][15][16]。
- 角色差异：苍墨「墨域加固」（稳健）、烟墨「烟走」（加速穿插）、泼墨「泼墨成域」（定向大范围扩散）、
  烟墨姬「墨雨漫天」（大范围喷溅）[4][9][19]。另有「百座历史名城各具守备特性」的说法 [7][16]。

> 注：检索中也混入了同名不同作（《墨战》武侠格斗／IO 涂地类）与明显拼凑的武将卡牌表，
> 一律未采信。上表只取多来源互相印证的部分。

## 二、与本项目战斗层的对照结论

用户口径：**「战斗层面和墨战类似，兵是城外来的、堡垒不自动归属，其余差不多；将领应该是一个特殊的兵，要真实战斗，不是一个框写着谁坐镇中央。」**

| 维度 | 墨战 | 本项目改前 | 本项目改后 |
|---|---|---|---|
| 兵力来源 | 城池产兵 → 派往别城 | `march` 命令抵达敌方城池进**城外大营** `camp` | **已一致，未改**。玩家把兵拖进城（`deployUnit`）才开打，城外扎营不等于交战 |
| 堡垒归属 | 占城即易主（胜利条件是占全图） | 攻方尽没／护卫散尽 / 主帅失护卫 → `judge` 提前判城破，`resolveBattle` 改 `owner` 与栅格色 | **删掉「护卫尽没 + 士气崩 → 立刻判城破」的自动判定**；主将必须实打实被击倒（阵亡／被擒）或含主将在内的守军全灭才结案。`resolveBattle` 的归属回写仍由战斗结果驱动，不凭空易主 |
| 将领 | 有角色／武将与技能卡，但主将多为阵法增益对象 | `c.commander` 是 `{state:'inOffice', col, row}` 的**状态框**：不进单位循环、不索敌、不出手、只被「近身 + 士气崩」触发被擒 | **是真兵**：`type:'jiangjun'`、有 hp/maxHp、进 `all` 循环、走 A*、索敌、出手、挨投射物、会死；死即崩己方士气并进终局 |
| 攻击 | 士兵自动攻击 + 卡牌／阵法改节奏 | 普通兵单一循环（找最近敌 → 冷却到打一下） | 将领**四种攻击样式确定性轮换**（直劈／横扫／突进／蓄势）+ **车悬式五次后撤休整** + 主动技能，不是同一个动画循环播放 |

## 三、将领真兵的落地清单

**配置**：`config/campaign.json`
- `units.jiangjun`：主将兵种（hp 取 `battle.commanderHp`，dmg 20，近战）。
- `battle.generalAttack.styles`：四种攻击样式，各有倍率／冷却／目标数／位移。
- `battle.generalSkill`：五技能冷却与效果参数（霸体、疑兵秒数、减伤倍率、连锁加重、休整节奏）。

**逻辑**：`src/siege-combat.js`
- `pickGeneralSkill(gen)`：按五维派生技能，一眼对得上每城守将——
  荀彧（智 92／政 96）「疑兵」、审配（统 74／智 78）「督战」、淳于琼「乱舞」、
  颜良（力 91）「锋矢突阵」、文丑（力 89）「乱舞」；程序化守将按最高维兜底。
- 技能与卡牌四类对齐：**速攻**（锋矢／乱舞）、**干扰**（疑兵：范围内敌人短暂丢失目标）、
  **发育**（督战：己方士气 + 友军回气）、**防御**（固守：减伤 + 回气）。
- 对照阵法：锋矢给**临时霸体**（`guardUntil`），八卦＝疑兵，车悬＝**每 5 击后撤休整**（`restUntil`）；
  连锁流＝技能后下两击加重（`empowered`），不是孤立放个技能。
- `generalAct()` 独立于普通兵循环；伤害一律走通用 `applyDamage`，所以将领真会掉血、真会阵亡。
- 将领**不随众溃散**，护卫散尽只置 `exposed`；开局 1.2s 必放一次技能，避免短战斗里文士守将整场无技能。
- 全部确定性：样式序号推进、`c.sec` 时间窗，不引入新随机源，双时钟／快照／重放逐字段一致。

**渲染**：`src/general-portrait.js` + `src/city-view.js`
- 立绘按**姓名 + 五维确定性哈希**派生：盔形（兜鍪两型／束发／儒冠）、长兵（戟／槊）、
  剑／羽扇／弓、袍色、披风三型下摆、旗章三型、须眉与面痕、盔缨。五名守将互不重样。
- 血条贴脚底随格位走；名字 + 技能名 + 冷却在立绘上方淡墨衬上，不压府衙建筑。
- 每种攻击样式 / 技能一种**不同的运笔动画**（直劈竖笔、横扫大弧、突进拖影、蓄势收拢环、
  乱舞四短笔、疑兵散点、督战涟漪、固守护罩、休整收势、锋矢长拖影），全部 canvas 路径，无位图。
- 动画时间基准统一取 `combat.sec`（策略层 `session.sec` 与它不同源，混用会让笔势永远不显示）。

**验证**：`tests/siege.test.mjs` 新增两条
- 「杂兵尽没但主将未倒 → 不判城破」，再打倒主将才终局。
- 「将领有技能、四种攻击样式轮换、会挨打掉血」。
实拍：`demos/preview-general-portraits.png`（五将立绘）、
`demos/preview-general-fengshi.png` / `preview-general-luanwu.png`（技能帧）。

## 四、两轮「查 → 对比 → 再完善」实际改了什么

**第一轮（设计前）**：查到水墨 RTS、画圈派兵、城池产兵与防御塔、结算卡牌、四类卡牌与角色技能。
对照后确认「兵力来自城外」「堡垒不自动归属」两条口径，决定**不动兵力与归属链路**，
只把「自动判城破」那条提前结案删掉，并把将领从状态框改成真实单位。

**第二轮（实现后）**：补查阵法与卡牌细则，得到三条直接改进——
1. 锋矢阵「前端将领临时霸体」→ 给锋矢技能加 `guardUntil` 与霸体环；
2. 车悬阵「每攻击 5 次后撤休整」→ 加 `restUntil`，攻击不再无限循环同一动画；
3. 连锁流「先破防后输出」→ 加 `empowered`，技能改变后续两击的性质。
另外把渲染里的 `ctx.arc` 全换成贝塞尔短弧（避免几何图元），并给立绘补披风／旗章／兜鍪两型，
让颜良与文丑这类同型武将也读得出差别。


### 第三轮（地图表现层做完后）

补查「派兵视觉 / 集群移动 / 视角」，得到两条直接可用的描述：

- 「水墨动态美学，**部队在移动过程中拖动的水墨痕迹**和倒塌建筑物的模糊效果在视觉上非常容易辨认」[21]
- 「**士兵在移动中留下的墨迹**，敌人在每次战斗后的消散，所有元素交织成一幅生动的画面」[22]

对照结论：本轮做的大地图行军队列，第一版「已走过的路」是一条从头到尾等宽等浓的
宽带，读成规划线而非墨痕。改成**逐段渐隐的拖尾**——每段二次曲线带确定性偏移，
浓淡与宽度都按 `u²` 随距队首的距离衰减，队首再散五笔淡墨点作消散。
实拍三帧差异像素 6414 → 10335 → 14515，队列与墨痕同步前进。

**不借鉴的机制**（统一口径）：天气改数值、建筑倒塌模糊、兵种合成与卡牌养成，
都不进本作；`condition.js` 已有的断粮行军系数是既有状态机制，不是照搬墨战。

补记两条口径澄清（用户本轮提出）：
- 「格相对于地图太小」→ 格网基准 46px 提到 92px，主格每 3 细格。
- 「应该是矢量图，为何保存成位图」→ 地图本体一直是 canvas 路径，PNG 只是实拍预览；
  另落一份真正可无限放大的 `demos/atlas-vector.svg`，demos 加「导出矢量」按钮。

## 四之补、第四轮补查：只借玩法层

用户口径收敛后，第四轮的取舍重新整理如下。**墨战那些合成、卡牌、归属机制
一概不借鉴**，查过只为确认边界；真正落进本作的只有玩法表现：

| 借什么（玩法层） | 墨战表现 | 本作落点 |
|---|---|---|
| 画圈选中 + 点目的地奔赴 | 画个圈选兵，点任意位置奔赴 [23][25] | 框选 → A* 行军插值（`motion` / `syncMotion`），大地图另有 `drawMarchers` |
| 部队移动拖出水墨痕迹 | 「拖动的水墨痕迹」[21]、「士兵移动中留下的墨迹」[22] | `drawMarchers` 逐段渐隐拖尾 + 队首散墨点 |
| 战斗后敌人消散 | 「敌人在每次战斗后的消散」[22] | `drawInkFade()`：读 `unitDown` 事件，五笔淡墨散开后化尽；纯渲染层 |
| 技能触发要有即时反馈 | 卡牌取得即生效、角色带技能 [24] | 将领自带 5 技能 + 冷却；释放瞬间浮技能首字墨字，随动画上浮淡出 |
| 将领是真兵、攻击不重样 | 角色形象各异、技能各异 [23][26] | 差异化立绘 + 血条 + 四种攻击笔势 + 车悬五次后撤休整 |
| 实时攻防、单局紧凑 | 实时策略、每局三五分钟 [25] | 派人进城才开打，命中／发矢／城门耐久／士气真实推进 |

**明确不借鉴**（一句话，不再逐条展开）：兵种合成／汉字 300 组合、技能卡养成与
战后选卡、雨雪改视野移速、倒塌建筑模糊、小兵牺牲降城防、最后一击定归属。
堡垒归属按用户既定口径「不自动易主」，由战斗结算回写。

## 四之补二、第五轮补查：框选「即时反馈」

用户口径仍是「只是借鉴玩法，不要兵种合成等」。本轮查框选手势与胜负反馈，
得到两条直接改变实现的问题：

- **「手指的框选和士兵接受指令都非常流畅，没有任何延迟」「我的决策和部署
  能够及时的在战略地图上反馈」** [28]。
- **手势形态有异说**：多数口径是「**下滑框选 / 用手指划出矩形区域**」[29][30][31]，
  只有部分介绍写「画个圈就能选中部队」[25]。
- 另有「士兵兼具经济属性、投入城池转血量与经验」[28]、「长按已选中士兵拖动
  指定集结点」[30]、「占领所有城池获胜／老家被破直接失败」[29][31]。

据此**再完善一处，并修一个真 bug**：

| 项 | 处理 |
|---|---|
| 框选圈看不见 | `lostpointercapture` 在 `mouseup` 后照常触发，原代码把它和 `pointercancel` 一起绑了同一个处理器，**把刚落下的 `circle` 立刻清成 null** —— 玩家画完圈看不到自己画的圈，正是 [28] 说的「反馈断了」。拆成两个监听：取消手势才清，捕获释放不清，交给 pointerup 的 800ms 定时器收尾 |
| 标准正圆 | `ctx.arc` 正圆 + 虚线阵列 → `inkRing()`：26 点低频形变的**一圈不规则运笔**，收笔留两小段缺口，不是圆也不是虚线；拖兵落点同改。选人逻辑一字未动 |
| 手势形态 | **沿用既有圆框选判定**，不为了对齐别家改成矩形；[25] 的「画圈」也是墨战公开口径之一 |
| 不引入 | 士兵转城池血量经验、长按指定集结点、占领全图／老家判负、日卡次卡与卡牌构筑 [28][29][30][31] —— 会动到兵力来源、存档与策略层，超出「只借玩法」 |

实拍：有圈帧 vs 圈消失帧差异 **2325** 像素，包围盒与 `circle` 的 `{x,y,r}` 吻合；
框选仍一次选中 9 兵，零 pageerror。
