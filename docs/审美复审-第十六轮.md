## 三、根因（不是调参能全救的）

1. **均匀扫格撒笔 = 纹样平铺。** `makeBg` 是 `while(y<H) while(x<W)` 逐格扫 +
   `rnd > 0.30+0.68*dens` 跳笔。而 `docs/背景层落地清单.md` 的
   **「本轮实拍推翻记录」第 1 条**早就写过：

   > 工笔层第一版按 21px 网格撒 2623 笔同款弧 → 实拍直接变成**纹样平铺**，
   > 已推翻为「低频簇场成簇 + 笔型四变 + 双勾约两成」。

   **同一个被自己否掉的画法又回来了**。这不是我主观挑刺，是仓库既有结论。

2. **15400 个色块 rect 底罩。** `svgWash()` 用 140×110 色块 + 高斯模糊近似连续场，
   浏览器里露出成行色阶；叠加 `density` 在秦岭—淮河一带的衰减，形成那条水平断层。
   `buildWash()` / `src/atlas.js` 的 `makeWash()` 同样按 `density` 设 alpha，页面也分层。

3. **格网默认压在画上。** `showGrid=true` 且导出 SVG 也把 `grid-fine` / `grid-major`
   写进文件。格网是「计里画方 / 上层逻辑界格」，压进纯矢量交付图，与
   `docs/毛笔笔势与古舆图参考资料.md` §三.11 的「形象画法」相冲。

4. **封面深色字压深底。** CSS 里 `.prologue h3` / `.proBeat` 用 `#20251f`，
   明显是给浅纸卡准备的前景色，实拍却落在墨底上。

5. **更根本的一条（本轮没动）**：整幅的构成是「连续场底罩 + 全图撒笔 + 细线符号」，
   本质是**数据可视化**。而资料里写得很清楚，古舆图主流是**形象画法**：
   「见山画山、见水画水」「以水系为脉络」「重绘顺序应是 **水 → 山 → 道 → 城**」。
   之前为了解决「灰色三角山 / 栅栏皴读成划痕」（README v0.6.0 一笔山脊实验），
   把山形整段删了，**结果全境图就没有骨架了**。这是用一个审美问题换来了更大的一个。

## 五、这轮**没有**解决的，以及为什么没动

改后 `B1` 依然是一张「撒了草屑的干净纸 + 几条细线 + 小字」：
**没有山的骨架、没有大河的势、没有城郭的形**，下半幅一大片青绿近乎空白。
也就是说，用户说的「很大的问题」如果指的是**整幅不像一张古画**，那还没解决。

调参救不了这一层——它是**技术路线**决定的。要根治得按形象画法补主体：
以水系为脉络，先立秦岭—太行—阴山—南岭几条主脊（脊线亮墨提光、两侧皴顺
笔势渐暗、成组而非逐格），再让城郭、关津、注记挂到山水上，而不是挂在格子上。
`docs/毛笔笔势与古舆图参考资料.md` §三.8/9/11 给了现成依据。

**这是方向项，不是 bug，我没自作主张动它**：它会重画 `src/atlas.js` 与 demos
的地貌构成、推翻「山脉整段删除」的既有结论、改变全部实拍与 SVG 指纹，代价和
风险都远大于本轮四处修正。按用户一贯口径（C1/C2 那次「得你先说做还是不做」），
**先请拍板**：

- **A · 保持现状**：只认本轮四处修正，全境图定位为「写意底图 + 史料注记」，
  把「无山形 / 无大河势」写进如实边界，不再折腾。
- **B · 补一层山势骨架（可开关）**：不换整套架构，只加一组按脊线成组的皴笔 +
  双勾大河，做成可切换的层；实拍 A/B 对比后再决定留不留。风险中等。
- **C · 换形象画法重画表现层**：按「水 → 山 → 道 → 城」重排 `src/atlas.js` 与
  demos，注记挂地物不挂格，主地图同步降迷彩密度、城名降层级。改动最大，
  会动到 265 单测里的视觉断言与两份 SVG 指纹，需要单独一轮 + 全量回归。

我倾向 **B**：先用最小代价验证「补了骨架是不是真的像画了」，再决定要不要走到 C。
但**这轮不默认执行**，等一句话。
