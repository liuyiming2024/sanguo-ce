# 软著登记「未使用 AI」承诺政策梳理

| 项 | 值 |
| --- | --- |
| 文档性质 | 后台开发用 · 白话 · 不进游戏；不是法律意见，以中国版权保护中心当前发布为准 |
| 整理日期 | 2026-11-20（Asia/Shanghai） |
| 触发缘由 | 本项目两路会话均为 AI 辅助，历次答复里把这条说成「地方办事指引、各地执行不一」，口径不准，本文件订正并给全本 |

## 一、一句话结论

**这是 2026-03-15 中国版权保护中心的全国统一新规，不是地方指引。** 核心是新版申请表签章页要经办人**亲笔手抄**一句「本软件确系人的独立开发，未使用 AI 开发编写代码、撰写文档或生成登记申请材料」，并签名、填身份证号；失实即列入版权登记失信名单并纳入个人征信。它管的是「**能不能拿到登记证书**」，不管「**你有没有著作权**」——后者自软件开发完成自动产生，登记只是初步证明。

## 二、官方原文与出处

- 中国版权保护中心《共同维护计算机软件版权登记良好生态》，**2026-03-15 18:00** 发布：「建立软件版权登记申请诚信制度，引入失信惩戒机制……优化更新后的申请表自发布之日起施行」。旧版申请表废止，用旧表提交**不予受理**。
- 新版签章页划线承诺全文（山东理工大学科技处转载的门户登录页提示）：「申请人认真阅读了登记指南，确认并声明本软件确系人的独立开发，未使用 AI 开发编写代码、撰写文档或生成登记申请材料。申请表中填写的软件功能和技术特点的相关内容与本软件实际情况相符。提交的全部申请材料内容真实……如有失实或欺骗，自愿承担列入版权登记失信名单及个人征信记录，并承担由此引发的法律责任及后果。」**以上划线部分内容请在下方手抄写**，另加经办人签名、身份证号码、盖章。
- 同步明确「经办人」是**申请人（机构）的内部经办人**，不是代理机构的联系人；责任穿透到申请主体内部人员，代理不能当挡箭牌。

> 订正旧口径：此前几轮说的「部分地方办事指引提到」「各地执行也不一」不准确。这是国家级唯一软件登记机构的统一动作、全国统一施行；真正仍不确定的是**涉 AI 个案如何裁量、能否以「如实披露 + 过程证据」替代那句绝对承诺**，这个要向中心核实，不是地区差异。

## 四、新表五处实质变化

1. **功能描述 200 字以内 → 500–1300 字**：须覆盖研发背景、核心架构、功能模块、技术实现、应用场景，杜绝模板化、空洞化。
2. **签章页手抄承诺 + 经办人本人签名 + 身份证号码**，黑色中性笔、文字标点原样照抄。
3. **诚信制度与失信惩戒**：提交虚假材料、非正常申请、恶意重复申报，列入版权登记失信名单，纳入个人/企业征信，并依法追责。
4. **三重/四重一致性核验**：申请表 ↔ 功能说明 ↔ 源程序（前后各 30 页）↔ 文档（用户手册/设计说明书），名称、版本号、开发完成日期、功能点须逐字对得上，一处不符即补正或驳回。
5. **明确四类「非正常申请」从严审核**：短期批量集中申报、技术与主营业务脱节的「虚研逐利」、材料抄袭造假/重复申报、**提交 AI 生成的模板化申报材料**。

补充实务口径（**非官方硬指标，属代理与律所解读，不作准**）：有平台称涉 AI 开发应补「人工优化代码记录、训练数据合法证明」，另有代理文章写「核心逻辑 ≥80% 人工设计」「需交《AI 开发合规声明》」。这些是降低补正风险的建议，不是中心公布的量化标准。某律所统计 2026 年 2–4 月普通登记补正率超 60%、下证率约 30%，同样是机构统计，不是官方数据。

## 五、常规材料与流程（后台速查）

- 自愿登记；著作权自开发完成之日自动产生，不论是否发表，证书是**权属的初步证明**。
- 申请表 + 源程序前 30 页、后 30 页（不足 60 页全交，每页 ≥50 行，页眉写软件全称与版本号、右上角页码，去空行）+ 用户手册或设计说明书 + 身份证明；合作/委托/受让须交相应合同或证明。
- 受理后 **60 个工作日**内审查；材料不齐 **30 日内补正**；审查通过公告 3 天发电子证书（与纸质同等效力）。官费 0 元，代理另计。
- 软件名不要带版本号、广告用语；软著主体须与将来小程序账号实名一致。

## 六、两个口径为什么「看着打架」

| | 司法（法院） | 行政登记（版权中心） |
| --- | --- | --- |
| 问的是 | 这东西是不是作品、归谁 | 能不能发这张证书 |
| 标尺 | **人的独创性智力投入**：构思、提示词与参数、多轮筛选、否决、修改、编排 | 申请表真实性 + **手抄「未使用 AI」承诺** + 材料一致性 |
| 对 AI 的态度 | AI 是工具，不是作者；用得深也可能构成作品 | 申报材料（代码/文档/申请表）不得由 AI 生成，隐瞒即失信 |

两者不是同一程序、不是同一问题，严格说不构成法律冲突；但**事实上有张力**：法院认「AI 辅助 + 人的判断」可版权，登记窗口却要求签一句绝对的「未使用 AI」。目前没有精确工具能画出「合法的人类智力投入 / 违规的 AI 自主生成」那条线，这也是各方呼吁「如实披露 + 过程证据」替代一刀切承诺的原因。

《著作权法实施条例（修订草案）》仍在征求意见、《十五五》规划把 AIGC 规则列入起草，方向是**统一登记标准、要求主动披露 AI 使用方式与人类贡献、强调过程性证据**；也就是说规则还在动，现在按旧口径硬提交，风险最高。

## 七、对本项目的具体结论（后台用）

**本项目两路会话都是 AI 辅助，逐字手抄「未使用 AI 编写代码/文档/申请材料」与事实不符。** 签字即产生责任，且明确挂钩失信名单与个人征信——所以**现在不要提交软著申请**，这不是「能不能拿到证」的技巧问题，是「能不能如实签」的问题。

正确动作，按优先级：

1. **提交前向中国版权保护中心核实当前受理口径**：AI 辅助但以人的设计、选择、修改为主，能否申报？能否以「如实披露 + 人工优化记录 + 创作过程证据」替代那句绝对承诺？旧表已废止，务必用 2026-03-15 18:00 之后的新表。
2. **等规则落地**：《实施条例》修订与《十五五》规划 AIGC 版权规则出台后再决定，别抢在过渡期里当样本。
3. **把证据链做厚，这正是各方一致强调的**：两份会话原件导出落盘、`git history` 每轮提交说明、`docs/创作决策日志.md`（整理版）、`docs/创作决策流水.md`（时间+具体事）、色值与视角的逐条否决记录、实拍台账。苏州蝴蝶椅案输就输在「再现不了过程、拿不出原始记录」，本项目恰好相反。
4. **权属不依赖证书**：不登记照样自动产生著作权；软著证书主要用在维权举证、项目申报、以及小程序游戏类目资质。若将来走 IAA 通道且游戏名不含英文/「软件」字样，按此前记录的通道口径可能只需「著作权自我声明」而非软著证书，从而绕开这一关——**该通道口径本轮未复核，提交前另查**。

## 八、与其余两条链的关系

- **权利链**：创作 → 智力投入 → 著作权自动产生 → 证据链 →（可选）登记证书。本文件只动最后一步。
- **上线链**：小程序备案（ICP，所有小程序都要）→ 游戏类目「出版」前置审批 → IAA（代备案授权书 + 著作权自我声明 + 自审自查报告）/ IAP（版号 + 软著 + …）。软著证书是**资质材料**，不是备案本身；游戏名带英文或「软件」会触发补软著，绕回第七节。
- **后台资源链**：云开发/云托管不产生任何权属，跟本文件无关。
