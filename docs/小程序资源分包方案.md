# 小程序资源分包方案（P4）

> 上一轮清单里 P1/P2/P3/P5 已由并行提交落地，**P4 是唯一剩下的适配项**。
> 本轮做的是**静态清点 + 分包建议 + 校验脚本**：不改 `miniprogram/app.json`，
> 因为没有小程序开发者工具 / 真机运行时，写进去也不能声称验过。端侧按平台格式
> 落地时照本文切即可。

## 一、先纠正一个口径

清单写「`assets/units/` 26 张 PNG」，那是 `trooper.json` 里 24 帧 + 2 sheet 的旧数。
实测 **63 个文件 / 32.79 MB**：

| 组 | 个数 | 大小 |
| --- | --- | --- |
| 合图 sheet | 4 | **13.32 MB** |
| 步态帧（单张） | 16 | 6.97 MB |
| 器械八向（单张） | 16 | 4.85 MB |
| 源底稿 JPG | 10 | 4.09 MB |
| idle 八向（单张） | 8 | 3.48 MB |
| tiny 档（单张） | 8 | 0.08 MB |
| `trooper.json` | 1 | ≈0 |

## 二、最实在的一刀：运行时只加载 4 张 sheet

`src/portrait.js:40-43` 只 `load()` 四张：

```
trooper-sheet.png        人形 8 向 idle
trooper-walk-sheet.png   人形 8 向 × 左右步
engine-sheet.png         床弩 / 抛石机各 8 向
trooper-tiny-sheet.png   手机 s<13 档轮廓
```

**其余 48 张单帧 PNG（15.38 MB）运行时零引用**，只是 `scripts/build_units.py`
的产物留档；10 张 `assets/units/src/*.jpg`（4.09 MB）是生成底稿，同样零引用。
所以：

> **运行时素材合计只有 13.32 MB**，比「32.79 MB 全搬」少了 19.47 MB。
> 清单口径「分包总 ≤20MB」若适用，13.32 MB 已在限内，不必先做压缩。

`docs/素材台账.md` 里那 48 张单帧与 10 张 JPG 标「待溯源 / 不新增引用」，
与这里的「不入包」正好对上：来源未闭环的东西，本来就不该进包。

## 三、建议分包

| 包 | 内容 | 说明 |
| --- | --- | --- |
| **首包** | 官渡本图 `bg+fg` + `soldier.js` 程序化回退 | **零 PNG 也能跑**；素材未就绪整队回退，不白屏（清单省力第 5 条） |
| **分包A「兵形皮肤」** | 4 张 sheet + `trooper.json`（13.32 MB） | 懒加载；加载失败继续走程序化回退 |
| **分包B「全境图」** | 全境 `bg+fg` | 按 `?map=quanjing` 懒加载，只带官渡一章时不需要 |
| **不入包** | 48 张单帧 PNG + 10 张源 JPG | 只留主工程供 `build_units.py` 一键复现 |

端侧 `app.json` 的 `subpackages` 写法依平台格式（微信小程序 / 抖音小游戏字段不同），
由端侧同学在开发者工具里落，**本轮不代写**。

## 四、校验脚本

```bash
node scripts/check-mp-assets.mjs
```

静态回答三件事：素材各组多大、`miniprogram/logic/` 镜像里有没有混进位图、
运行时 4 张 sheet + 索引齐不齐。异常真退出（退出码 1）。当前输出：

```
✓ P4 静态校验通过：镜像零位图、运行时 4 sheet + 索引齐、单帧与底稿未混入
```

它**不**做真机体积测量、不测加载耗时、不验证平台分包字段 —— 那些必须在
开发者工具里跑。脚本里也写明了这句，不假装有能力。
