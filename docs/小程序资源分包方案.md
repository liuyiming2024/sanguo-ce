## 两处前提错误

**① 「首包带官渡本图 `bg+fg`」「分包B 全境图 `bg+fg` 懒加载」——不成立。**
舆图是 `src/guandu.js` / `src/atlas.js` 的**程序化离屏画布**，仓库里 `.png`
字面量 0 处，随渲染层代码走，不占二进制体积。清单里「按章分包两张舆图」
这条前提本身就不对，对方已核清。

**② 「运行时 13.32 MB 在分包总 ≤20MB 限内」——口径用错。**
微信是**单个分包 ≤2 MB**（主包同样 2 MB），总 ≤20 MB。4 张 sheet 里
**3 张各自就超 2 MB**，直接声明 `subpackages` 会失败；只有
`trooper-tiny-sheet`（71 KB）可与逻辑层同进主包。总 20 MB 不是这里的瓶颈，
按总数判断会得出「已在限内」的错误结论。抖音主包 ≤4 MB / 分包总 ≤20 MB，
同样卡在单张 sheet。

## 仍然成立、且两边一致的部分

- 运行时只加载 `src/portrait.js:40-43` 里 **4 张 sheet + `trooper.json`**，
  合计 **13.32 MiB**（对方脚本从 `load(...)` 正则解析，不手写清单，更稳）。
- **48 张单帧 PNG（15.38 MB）+ 10 张源底稿 JPG（4.09 MB）运行时零引用**，
  不入包，只留主工程供 `scripts/build_units.py` 一键复现。
- 首包 **0.20 MiB / 零位图** + `soldier.js` 程序化回退 +
  `src/platform/mini-map.js` 零位图格网，可以先跑起来，不必等资源分包。
- **B6** 两处存档规范化表示差异（`chapterEnteredTurn` / `fort`）都 falsy、
  不进判定，按存档 JSON 比对即可，**不改 `campaign.js` / `persist.js` 核心资产**。
  两边结论一致。
