# 全境两章纪事底本（后台开发用 · 白话 · 不进游戏）

> 本文是 `config/story.json` 第九、第十回与 `config/historica.json` 本纪门「全境两章」的白话底本。
> **凡此处写的出处考辨、纪年校正、为什么某个地名没进三十城、为什么事件不改归属、哪个字段落哪个文件，一律不进游戏内界面。**
> 游戏内只留：章回页的半文言叙事、战报列表的「纪事」一条、邮件一封、典籍本纪门文言一条。
> 实施总纲见 `docs/建安五年官渡舆图史料汇总.md` §12，全库资料总目见 §16，地理数据底本见 `docs/全境州郡取数表.md`。

## 一、这一轮到底补了什么

全境两章在 v0.9.4 落地时只是骨架：有 `beat / historical / source / goal / reward / choice / onEnter.report`，但叙事偏「说明书」，句子里还混着「点地、下令、推旬、看战报」「凡所下军令，仍入同一道命令日志，隔旬快进与实时同解」这类工程词。按 §15 第 10 条「游戏内不出现调试语」，这本来就不该留在章回页里。

本轮补三件，全部复用既有机制，**没有新增任何玩法系统**：

| 项 | 落点 | 机制来源 |
| --- | --- | --- |
| 章回文案 | `beat` / `historical` / `source` 重写 | `src/ui-shell.js` `pageStory()` 原本就渲染这三段 |
| 州郡事件 | `onEnter.city` / `onEnter.intel` | `src/story.js` `advanceChapter()` 原本就支持 `city / intel / flags / report / mail` |
| 纪事 | `onEnter.report` / `onEnter.mail` | `pushReport()` 与 `src/story.js` `allMails()` |

顺手补了一个一直存在的真缺口：**开篇章的 `onEnter` 从来没生效过**。`advanceChapter()` 只在「推进到下一回」时应用 `next.onEnter`，而新局是装配层直接 `state.chapter = story.chapters[0].id`，从不经过推进——所以官渡第一回的「檄至许都」、全境第九回的「别展全境」这两条入场纪事，写是写了，玩家从来看不到。详见 §五。

## 二、纪年与章回对照（时序是这轮最要紧的校正）

| 回 | 游戏内 `era` | 史实依据 | 原本的问题 | 本轮处理 |
| --- | --- | --- | --- | --- |
| 第九回 州郡棋布 | 建安六年 三月 | 《三国志·魏书·武帝纪》：「六年春，公就谷东平之安民，粮少，不足与河北相支」；「夏四月，扬兵河上，击绍仓亭军，破之」；「秋九月，公还许」 | 原 `historical` 只泛写「公还许，河北诸郡多举城邑降」，把不同月份的事揉成一句；「多举城邑降」其实已写在官渡第八回「河北既定」里，两回重复 | 改为按春 / 夏 / 秋三句分列；形势（袁氏四州、荆州、江东、益州）另起一句，标为「是时」，不系具体月 |
| 第十回 南望荆襄 | 建安七年 正月 | 《武帝纪》：「七年春正月，公军谯」；「绍自军破发病，夏五月薨」；《蜀书·先主传》刘表使刘备屯新野；《魏书·李典传》备北侵至叶，公遣惇、典拒之 | **原 `historical` 写「绍薨，谭、尚争立」放在建安七年正月，把五月的事提前了四个月**；原 `beat` 还写「行台不别置一局，亦不别立一法」这类机制话 | 叙事只写「绍发病，谭、尚各树党与」；薨与争立放进 `historical` 作史注并明写「夏五月薨」——与官渡第八回 `historical` 的预告口径一致，不算躐进 |

`minTurn` 仍是官渡八回之后的 42 / 48，全境开局由装配层重映射为 0 / 6（见 `docs/全境州郡取数表.md` §三第 6 条）。**重映射只动进度门槛，不动 `era` 与史注**，所以界面上仍显示建安六年 / 七年，不会变成「建安五年正月开了全境图」。

## 五、开篇章 `onEnter` 缺口（工程记录，白话）

- 症状：`src/main.js` 的 `newCampaign()` 里写 `s.chapter = story.chapters[0].id` 且 `s.reports = []`；`advanceChapter()` 里只有 `next.onEnter` 被应用。于是 `ch1`（官渡）与 `ch9`（全境）这两条 `onEnter.report` 从未进过战报列表。
- 修法：新增 `src/story.js` `openingDispatches(story)` 纯函数，只返回 `{ chapterId, flags, report, mail }`，**不改 state**；`city / intel` 仍归推进时应用，避免开新局就改城池数值、把回归基线全挪一遍。
- 装配层三处：`newCampaign()` 注入 `storyFlags / storyMails / reports`；`boot()` 与「新开一局」按钮各自把全局 `reports` 同步成 `state.reports`（原来一个没同步、一个直接清空）。
- 连带影响：官渡本图开局现在也能看到「檄至许都」这条纪事，与全境一致。`scripts/smoke.mjs` 那条「空场不再是一整块纯黑」的断言原本只认空态文案「尚 无 战 报」，改成同时认非空态卷末题记「逐条而书」，并加一条「开篇章入场纪事可见」的断言。**这是修 bug 顺带改断言，不是放水**。

## 七、重难 · 疑点（白话，琐碎也放这里）

1. **官渡第八回与第九回的接缝**：第八回 `historical` 已经写了「冀州诸郡多举城邑降者」「七年五月绍薨」，第九回不能再说一遍「河北诸郡降」，否则玩家连着翻两回会读到重复。所以第九回改从「六年春就谷安民」起，把「形势」与「事件」分开写。
2. **新野、叶为什么没进三十城表**：全境图幅 33° / 144 列 ≈ 0.23° 一格，许都—阳翟只隔 1.4 格；再塞新野、叶这种县级点位，点城会互相盖掉城门（见 `docs/全境州郡取数表.md` §三第 1 条）。所以史事照写「北侵至叶」，但州郡事件挂在宛（南阳郡治）与襄阳上，**这是玩法层的代点，不是把叶搬到宛**。真要较真，得先扩城表与重跑逐城 A*，不在本轮范围。
3. **事件为什么不改 `owner`**：三十城的 `cao / yuan / liu` 是三色玩法约束，「liu」兼表刘表、刘璋、孙氏、张鲁，本来就不是建安五年实属版图（`docs/全境州郡取数表.md` §三第 3 条）。若章回入场直接把邺、蓟改成曹属，等于用一条剧情数据把玩法三色判成史实，还会顺手改掉开局领地数、`citiesGain` 基线与存档指纹。所以只动驻军 / 城防 / 士气 / 情报。
4. **「谭、尚各树党与」是 B/C 混合**：《武帝纪》明写绍发病、五月薨、谭尚争立（A）；但「蓟、晋阳军心浮动」是本作由河北动摇推演出来的（C），史书没有这句话。游戏内纪事把它与邺合写成一句，属叙事概括；**不得**据此在 `docs/东汉郡国今地核查待核清单.md` 里立为确定数据。
5. **`intel` 的 `source` 写「斥候 / 章回」**：`writeIntel()` 从 `state.cities` 当场取驻军 / 城防 / 士气，不是史料数据。别把它当成「斥候查到了史实」，也别在界面里显示这个来源字符串以外的解释。
6. **章回 `era` 与 `minTurn` 不是一回事**：`era` 是建安六年三月 / 七年正月（世界内时序），`minTurn` 是 42 / 48 接在官渡八回之后（进度门槛），装配层全境开局把后者重映射为 0 / 6。改文案时只动 `era` 与史注，**不要**顺手改 `minTurn`，否则 `canAdvance()` 的「待时至」文案会与章回月份对不上。
7. **本纪门文言不要越写越长**：`config/historica.json` 已有一条舆地门「十三州别图」，本轮只在**本纪门**补「全境两章」。两门分工是「时序」与「图幅」，不要把坐标、州郡表、可信度再塞进文言卷；静态自检会拦 URL、白话形制词与出土年份。
