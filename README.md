# 三国策 · 官渡（v0.3.0）

> 建安五年（200）豫兖战线，**144×108 栅格沙盘** + 率式整套界面 + 城池布阵小地图 + 两端并行双时钟 + 本机存档。
> 这是**独立的新代码库**，不是给原横版火柴人换皮。原 `stick-war` 保留为回归基线，
> 后续会作为「点攻城时内嵌的战斗子模块」接入；本轮尚未接入。

[在线试玩](https://liuyiming2024.github.io/sanguo-ce/)

## v0.3.0：整套界面 / 手机会话 / 收红与纸性

### 1. 率土式界面从头到尾补齐

底部主菜单 11 个 Tab，每个都是全屏子页面，带 `‹ 返回` 与 `×`，**Esc 逐级退出**；从 Tab 切页会重置导航栈，不会压出十几层。

| 页面 | 内容 |
| --- | --- |
| 内政 | 城主府居中、左军事右内政的**设施俯视图**（17 座设施）；点进详情看效果、升级消耗、前置城主府等级；税收 / 交易 / 坚守 / 征兵快捷内政 |
| 武将 | 在任与在野分栏；详情是**五边形雷达 + 五维条 + 竖排名 + 印玺**，不是圆圈里一个汉字 |
| 战法 | 8 个 S/A/B 级计策，军师零伤害辅助，无魔法兵种 |
| 部队 | 大营 / 中军 / 前锋三位置编成，校场等级解锁部队数，可点空位配将 |
| 出征 | 目标情报 + 我方兵力 + **胜负预判**（兵不血刃 / 损失在所难免 / 杀敌一千 / 敌军兵力强盛）+ 行军回合 + 体力消耗；出征才扣 20 体力 |
| 战报 / 邮件 / 任务 / 同盟 / 天下 / 系统 | 实时从 `state` 派生，任务有进度与领取，天下按势力列城池与领地，系统含存档与省电开关 |

顶部 HUD 补了势力值 / 铜钱 / 政令 / 天气；右下竖排地图工具。所有页面数据都从策略层实时读，不是写死的假界面。

### 2. 文治页反纸，武备页留墨

`ui-shell.js` 按 `PAPER_ROUTES` 给内政、任务、邮件、同盟、天下、系统、玩法反一张**蚕白纸底**（纸面墨字、右下朱印、金线收边），而武将、战法、部队、出征、战报仍是墨底。头部一律墨色，一深一浅，翻页才有节奏——「玄黑 / 绛红 / 蚕白」三色叙事这才真正立住。

**收红**：朱砂只留给不可逆动作（确认出征、新开一局）与出血信息（战报判定、败报），其余层级——关闭按钮、主按钮、badge、章节竖杠、任务标签、日志边线、星级——全部交给金的明度差。同时撤掉 `scrHead::before`、`cityGround::before`、`menuCard::before` 等内层线，只留外框 + 一处角饰。

### 3. 手机：状态属于这局，不属于这个页面

- **存档**：`persist.js` 把整局压成纯 JSON。15552 格地形按 seed 重建，只存与初始地图不同的格子（通常几十格）；`facilities / armies / copper / settings / reports / claimedTasks / forces / intel / orders / snapshot / camera` 全在存档边界内。RNG 状态随快照序列化，恢复后序列不分叉。
- **自动存档**：`visibilitychange` / `pagehide` + 每 3 旬节流。主菜单出现「继续上一局」，刷新、锁屏、切 App 回来还是刚才那一局。
- **双指捏合缩放 + 中点锚定**、单指平移、点击阈值区分；窄屏点选**吸附**到 3×3 内最近可通行格。
- **静止停绘**：关掉自动推进且无交互时不再每帧 blit 8.9M 位图，`zoom / pan / 回合 / 子界面` 才唤醒；城池小地图有动画时仍保持绘制。
- 系统页可切换停绘与吸附；`prefers-reduced-motion` 关动画；`:focus-visible` 给键盘落点；div 卡片补 `role="button"` + `tabindex` + Enter/Space；触控目标 ≥44px。

### 4. 机制坑（这一版收掉的）

| | 修法 |
| --- | --- |
| 装饰层 `z-index:200/201` 压在开局菜单、全屏页、toast 之上 | 降到 `2/3`，恰好夹在地图(1) 与 UI(15+) 之间 |
| `body::after` 用 `90deg + 0 1px` 只渲出两个金点 | 改贯通渐变，且只留一条外框金线 |

| `.x` 没有基类，`position:absolute` 靠碰巧匹配 | 抽基类；`.scrHead{position:relative}`、`.scrHead .x{position:static}` 回归 flex item |
| flex 子项 `min-width:auto` 撑爆顶栏 | `.res` / `.hudExtra` 补 `min-width:0` |
| 矮屏 `#battleOverlay{overflow:hidden}` 硬裁掉底部按钮 | 整屏 `overflow-y:auto` + canvas `flex:0 0 42vh / 38vh` |
| `--gold2` 4.43:1、`.tiny` 4.23:1 低于 AA，`.locked` 又叠 `.42` | 提亮到 `#a08a58` / `#8b957f`，锁定项 `.58` |
| `--serif` 首位 `Songti SC` 仅 macOS，Windows 掉黑体 | `Noto Serif CJK SC` / `Source Han Serif SC` 提前，`SimSun` 兜底；竖排名 38→32px、字距 10→6px |

## v0.2.0：清晰度 / 指令层 / 城池布阵

### 0. 两个界面，职责严格分开

| | 大地图 (`map-render.js`) | 城池小地图 (`city-view.js`) |
| --- | --- | --- |
| 视口 | 可拖动、可缩放、`全图`、右下角缩略导航 | **固定视口，一屏放下 24×16 城内网格；不拖动、不缩放** |
| 交互 | 只**下指令**（12 类，全部带 `arriveTurn`） | 只**调兵**：拖拽把单位在「城外大营 ↔ 城内」之间部署；圆框选 + 二次拖拽定方向；单击单兵接管 |
| 绘制 | 地貌离屏预渲染，信息层屏幕空间 | 全部主画布按屏幕像素绘制 |

### 清晰度为先

`tilePx` 12 → **24**，离屏位图 `3456×2592`。更关键的是分层：**城名、山水注记、关隘名、土地等级、图廓、比例尺全部移到屏幕空间绘制**，字号/线宽按 `1/camera.scale` 换算，永远是固定物理像素，不随缩放被插值糊掉。山形/树冠/河纹/官道线宽与对比度同步提高；接近 1:1 才用高质量插值，缩到很小时用最近邻保住细线。

### 大地图不止「占领地块」

`claim / march / scout / develop / buildFort / transfer / garrison / withdraw / recruit / fireDirectional / stratagem / reinforce` 共 12 类，配置与指令层一一接线：

- **屯田**：己方地块 `level+1`，重算四资源产出
- **筑垒**：己方地块生成垒寨、通行代价下降
- **侦察**：写 `intel` 情报（守军/城防/士气/归属），不改兵力、不开战
- **调动 / 驻守**：只对己方城；**出征 / 增援**：只对敌方城
- **撤兵**：从敌城大营收兵回出发城；**撤令**：退还尚未出发的兵员与已扣资源
- 资源池是**可花费的累积库存**，与「每旬流量」分离（`state.resources` vs `state.yield`）
- 「在途军情」面板列出所有命令、预计抵达旬、路径格数，可逐条撤令

### 己方在城内，敌方在城外扎营

`campaign.forces[cityId] = { inside, camp }`，每个元素是独立实体（id / 兵种 / 阵营 / hp / 格位 / 人数 / 选中态）：

- 开局各城守军展开为**城内**实体
- 抵达**己方**城 → 新部队进 `inside`（布防）
- 抵达**敌方**城 → 新部队进 `camp`（**城外扎营**），城内是守军
- 小地图把 `camp` 里的兵**拖进城里 = 派人进去打**，拖回 `camp` = 撤出；这就是「先打着、后续投入、中途退出」的落点

### 两端并行的架构级约束

退出子界面拍快照时**深拷贝 `forces`**；恢复时按 **unit id 合并**，不是无条件覆盖 —— 否则离开期间策略层并行抵达的援军会被旧快照冲掉，直接违反「两端并行」。同时把 `createCityView` 改成**单例 + `AbortController` 一次性绑定**，切换城池只换 `getCityId()`，避免重复监听导致一次拖拽触发多次部署。

## v0.1.0 做了什么

### 1. 足够复杂的真实地块地图

不再是 12 个城点连几条直线，而是 **15552 个格子**，每格有 `type / base / level / yield / cost / owner / cityId`。

- **真实地理骨架**：汉末黄河故道（荥阳北→延津→白马→黎阳）、颍水/汝水/鸿沟/淇水/荡水、圃田泽/荥泽/大野泽、嵩山—箕山—太行—历山、虎牢关/轘辕关与四处津渡；十二座史实名城（许都、邺、汝南、陈留、黎阳、濮阳、阳翟、谯县、中牟、白马、延津、官渡）。
- **分层程序化地形**：确定性 fbm 高程场叠加山脊抬升与河谷压低，再刷泽薮、水系、城郭、官道、关隘、津渡。道路沿 `via` 折线蜿蜒，不是两点直线。
- **画风**：绢帛底纹 → 地貌色块 → 三角山形与等高线 → 树冠/田埂/芦苇 → 河面波纹与河岸 → 官道双线车辙 → 城郭垛口、角楼、城门洞、旗纛 → 竖排城名与山水注记。刻意不做「圆圈中间写汉字」。全离屏预渲染一次，主画布只做视口 blit + 动态层。
- **零位图、零墙钟、零 `Math.random`**：同一 seed 生成结果逐字节一致（单测守这条）。

### 2. 率土之滨式的地块规则

| 机制 | 实现 |
| --- | --- |
| 土地等级 1–9 | 按高程、林地、距城加成推导，缩放足够时显示角标 |
| 四资源时产 | 木/石/铁/粮按 `base × level` 逐格累加到势力资源池 |
| 连地铺路 | 目标格 8 邻域内必须有己方领地才能出征，`claim` 命令逐格推进 |
| 行军需要时间 | **A\* 8 向寻路**（禁止斜穿两个障碍角），累计 `tile.cost` 折算 `arriveTurn`；山地/大河不可通行，关隘与津渡是唯一通道，官道代价 0.55 最快 |
| 命令是计划任务 | `Order { arriveTurn, atSec, path }` 存进在途队列，绝不即时生效；到达时结算 |
| 时间驱动 | 全局累计模拟秒 `turn × secPerTurn`；策略层、战斗层、邮箱共用这一个基准 |

自检实测：`许都 → 邺` 78 格 / 88.8 代价 / 5 旬，每旬约 18.9 格；十二城两两 A\* 全连通（城门被汝水/山脉封死时自动刷短堤道接线）。

### 3. 三国策式的策略层

- **内政/回合**：1 回合 = 1 旬（建安五年二月上旬起），人口增长、粮草收支、募兵、城防修复、疲劳恢复。
- **隐藏属性**：士气 / 疲劳 / 粮草 / 警觉 / 阵型完整度都不直接显示，只通过溃散、被擒、征兵上限、行军速度间接生效。对齐三国策「士气决定行动顺序与攻防倍率、粮尽则士气掉」的思路（本轮先落漂移与围城惩罚）。
- **军师是辅助**：`junshi` 零伤害、无投射物，只有鼓舞/疑兵/火攻计策槽。**没有巫师、巨人、矿工、法球、召唤、眩晕**——三国背景里这些东西违和。
- **兵种**：刀盾、长枪、弓弩、床弩、抛石机、重甲步、军师。所有 `projectile != null` 的远程单位都能吃「圆框选 → 二次拖拽定方向」的齐射指令，不只弓手。
- **单方但可任选**：开局选曹操 / 袁绍 / 刘备，其余势力由 AI 每两旬决策（优先铺路，其次出征），确定性 RNG。

### 4. 两端并行，不是冻结

这是最容易写错的一条。战斗层**不是一直空转的后台进程**：

```
enter(snapshot, nowTurn) → 用同一个 advanceBattleStep() 固定步长空跑到 nowTurn
                         → 接上 rAF 实时循环
leave()                 → 拍 BattleSnapshot { sec, campaignTurn, rngSnapshot,
                                              pendingOrders, morale, cityWall, ... }
                         → 战斗层完全停跑；策略日历照常走
```

- 「隔一个月再点进去」**不另写解析结算公式**，而是拿同一份纯逻辑以 1/60 秒无渲染空跑几千步（毫秒级）。因此「一直盯着打」和「离开再回来」结果**必然一致**——单测逐字段比对 `sec / stepsRun / morale / cityWall / pendingOrders`。
- 邮箱事件带 `atSec` 时间戳，按**整数步索引**回放，不是月末一次性倾倒。既避免 `1/60` 累加 480 次后的浮点漏判，也避免放宽容差导致的重复消费。
- `rngSnapshot` 可序列化，快进后随机序列不分叉。
- 终局回写以 `battleEndTurn` 为准，**绝不回退到开战那一回合**；城池易主时同步栅格归属，地图颜色与策略状态不分叉。

### 5. 画风与交互

- 拖动 >140px 平移地图、短拖画圆框选、单击看格详情、双指/滚轮/`＋−` 缩放、回中。
- 每个能进的层都有醒目 `×`：`Esc` 分级 `玩法 → 战场 → 信息卡`。窄屏信息卡变底部抽屉。
- 顶栏实时显示日期、势力、四资源与已占领地块数；信息卡给地形、等级、四资源时产、通行代价、归属。

## 已知限制（下一轮接）

- **城池小地图目前是布阵层**：有网格、独立单位、拖拽部署、框选/定向指令、单兵接管标记；但**没有真实战斗结算**（伤害、投射物飞行、士气溃散、主帅被擒判定都还没接）。快照只保留部署与时钟，不推进伤亡。
- **界面数据是展示层**：设施等级、武将、战法、部队编成、任务、邮件已可交互且随存档持久化，但设施对行军速度 / 兵种克制 / 战损的实际加成、武将五维对行军与胜负的影响、战法在战斗层的消费、同盟捐献加成，都还没接进 `campaign` / `battle-session` 的数值口径。
- **双指捏合已在装配层实现**，但真机多点触控与惯性 fling 未做（无真机环境）；镜头变换仍是瞬跳，没有缓动。
- 存档是**本机 localStorage 单档**，没有账号、云同步、多档位与服务器权威时间；你定的是单机沙盘，这条属口径而非缺陷。
- 旧 `stick-war` 的横版战斗尚未作为子模块接入；接入时只保留伤害/状态/箭矢/投射物/确定性 RNG，坐标要从一维 `x` 换成 `Vec2`，胜负条件从「雕像血量」换成城门/府衙 + 主帅状态机，矿工与宝石整条不挂载。
- 武将只有「某城守将」占位，暂无五维（统率/武力/智力/政治/忠诚）、录用/解雇、带兵上限与俘虏招降。
- 定向齐射指令已进邮箱，但战斗层尚未消费它；近战单位收到同一指令时的「突击」也只是状态标记。
- 没有合击、兵种相克矩阵、训练度分段、米仓补给范围、阵法（赤火/玄水/八阵图）——这些是三国策里士气系统的核心，留到策略层第二轮。
- 没有同盟、赛季、多人、云存档；`localStorage` 也还没接，快照目前只在内存里。
- 地块产出是「按领地逐格累加」，没有名望上限、领地上限与土地开发计略。
- 战斗服/调度服是本地单进程模拟，没有服务端任务调度与幂等日志。

## 参考口径

率土之滨：225 万格土地与等级产出、连地铺路、行军时间由距离与兵种速度决定、武将兵力兼作 HP 与伤害加成、攻城值削耐久、SLG 服务端按时间队列驱动任务而非玩家即时触发（网易官方「地图玩法」「武将介绍」及 SLG 服务端架构资料）。三国策：内政/战斗两阶段、士气决定行动顺序与攻防、军粮与鼓舞影响士气、军师为辅助、兵种相克与训练度（官网「内政篇」「战争篇」「基础兵法」）。本库取两者的**结构**，不复制数值。
