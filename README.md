# 三国策 · 官渡（v0.1.0）

> 建安五年（200）豫兖战线，**144×108 栅格沙盘** + 攻城子界面的双时钟骨架。
> 这是**独立的新代码库**，不是给原横版火柴人换皮。原 `stick-war` 保留为回归基线，
> 后续会作为「点攻城时内嵌的战斗子模块」接入；本轮尚未接入。

[在线试玩](https://liuyiming2024.github.io/sanguo-ce/)

## 这一版做了什么

### 1. 足够复杂的真实地块地图

不再是 12 个城点连几条直线，而是 **15552 个格子**，每格有 `type / base / level / yield / cost / owner / cityId`。

- **真实地理骨架**：汉末黄河故道（荥阳北→延津→白马→黎阳）、颍水/汝水/鸿沟/淇水/荡水、圃田泽/荥泽/大野泽、嵩山—箕山—太行—历山、虎牢关/轘辕关与四处津渡；十二座史实名城（许都、邺、汝南、陈留、黎阳、濮阳、阳翟、谯县、中牟、白马、延津、官渡）。
- **分层程序化地形**：确定性 fbm 高程场叠加山脊抬升与河谷压低，再刷泽薮、水系、城郭、官道、关隘、津渡。道路沿 `via` 折线蜿蜒，不是两点直线。
- **画风**：绢帛底纹 → 地貌色块 → 三角山形与等高线 → 树冠/田埂/芦苇 → 河面波纹与河岸 → 官道双线车辙 → 城郭垛口、角楼、城门洞、旗纛 → 竖排城名与山水注记。刻意不做「圆圈中间写汉字」。全离屏预渲染一次，主画布只做视口 blit + 动态层。
- **零位图、零墙钟、零 `Math.random`**：同一 seed 生成结果逐字节一致（单测守这条）。

### 2. 率土之滨式的地块规则

| 机制 | 实现 |
| --- | --- |
| 土地等级 1–9 | 按高程、林地、距城加成推导，缩放足够时显示角标 |
| 四资源时产 | 木/石/铁/粮按 `base × level` 逐格累加到势力资源池 |
| 连地铺路 | 目标格 8 邻域内必须有己方领地才能出征，`claim` 命令逐格推进 |
| 行军需要时间 | **A\* 8 向寻路**（禁止斜穿两个障碍角），累计 `tile.cost` 折算 `arriveTurn`；山地/大河不可通行，关隘与津渡是唯一通道，官道代价 0.55 最快 |
| 命令是计划任务 | `Order { arriveTurn, atSec, path }` 存进在途队列，绝不即时生效；到达时结算 |
| 时间驱动 | 全局累计模拟秒 `turn × secPerTurn`；策略层、战斗层、邮箱共用这一个基准 |

自检实测：`许都 → 邺` 78 格 / 88.8 代价 / 5 旬，每旬约 18.9 格；十二城两两 A\* 全连通（城门被汝水/山脉封死时自动刷短堤道接线）。

### 3. 三国策式的策略层

- **内政/回合**：1 回合 = 1 旬（建安五年二月上旬起），人口增长、粮草收支、募兵、城防修复、疲劳恢复。
- **隐藏属性**：士气 / 疲劳 / 粮草 / 警觉 / 阵型完整度都不直接显示，只通过溃散、被擒、征兵上限、行军速度间接生效。对齐三国策「士气决定行动顺序与攻防倍率、粮尽则士气掉」的思路（本轮先落漂移与围城惩罚）。
- **军师是辅助**：`junshi` 零伤害、无投射物，只有鼓舞/疑兵/火攻计策槽。**没有巫师、巨人、矿工、法球、召唤、眩晕**——三国背景里这些东西违和。
- **兵种**：刀盾、长枪、弓弩、床弩、抛石机、重甲步、军师。所有 `projectile != null` 的远程单位都能吃「圆框选 → 二次拖拽定方向」的齐射指令，不只弓手。
- **单方但可任选**：开局选曹操 / 袁绍 / 刘备，其余势力由 AI 每两旬决策（优先铺路，其次出征），确定性 RNG。

### 4. 两端并行，不是冻结

这是最容易写错的一条。战斗层**不是一直空转的后台进程**：

```
enter(snapshot, nowTurn) → 用同一个 advanceBattleStep() 固定步长空跑到 nowTurn
                         → 接上 rAF 实时循环
leave()                 → 拍 BattleSnapshot { sec, campaignTurn, rngSnapshot,
                                              pendingOrders, morale, cityWall, ... }
                         → 战斗层完全停跑；策略日历照常走
```

- 「隔一个月再点进去」**不另写解析结算公式**，而是拿同一份纯逻辑以 1/60 秒无渲染空跑几千步（毫秒级）。因此「一直盯着打」和「离开再回来」结果**必然一致**——单测逐字段比对 `sec / stepsRun / morale / cityWall / pendingOrders`。
- 邮箱事件带 `atSec` 时间戳，按**整数步索引**回放，不是月末一次性倾倒。既避免 `1/60` 累加 480 次后的浮点漏判，也避免放宽容差导致的重复消费。
- `rngSnapshot` 可序列化，快进后随机序列不分叉。
- 终局回写以 `battleEndTurn` 为准，**绝不回退到开战那一回合**；城池易主时同步栅格归属，地图颜色与策略状态不分叉。

### 5. 画风与交互

- 拖动 >140px 平移地图、短拖画圆框选、单击看格详情、双指/滚轮/`＋−` 缩放、回中。
- 每个能进的层都有醒目 `×`：`Esc` 分级 `玩法 → 战场 → 信息卡`。窄屏信息卡变底部抽屉。
- 顶栏实时显示日期、势力、四资源与已占领地块数；信息卡给地形、等级、四资源时产、通行代价、归属。

## 目录

```
config/campaign.json       唯一配置源（日历/势力/兵种/隐藏属性/地形/城内网格/画色调色板）
src/map-data.js            真实经纬度锚点：城池、汉末黄河、支流、泽薮、山脊、关隘、道路折线
src/terrain.js             144×108 确定性栅格生成 + 派生等级/产出/代价/归属
src/pathfind.js            8 向 A*、连地判定、可出征格、占领、全图连通自检
src/campaign.js            纯逻辑策略层：回合、地块产出、在途命令、AI、战斗终局回写
src/battle-session.js      双时钟会话：快照 / 离开停跑 / 同算法快进 / 邮箱按步回放
src/map-render.js          分层程序化地形渲染（离屏）+ 领地边界 Path2D 缓存 + 动态层
src/main.js                装配层：唯一引用 DOM / rAF 的地方
scripts/check-map.mjs      配置/地形/连通性/导航/指纹静态自检
scripts/smoke.mjs           28 项 Playwright 页面可达性断言
tests/                     28 个 node:test 单测
```

## 运行

```bash
npm test          # 28 个单测
npm run check     # 地图/连通性/导航自检
npm run smoke     # 起本地服务 + 28 项浏览器烟测
```

纯静态站点，无构建步骤；`index.html` 用 `?v=0.1.0` 给 ESM 与 CSS 打缓存指纹。

## 已知限制（下一轮接）

- **攻城子界面目前是骨架**：只有快照/快进/邮箱，没有城内网格战斗、单兵实体、寻路与真实结算。`battle.gridCols/Rows` 已留配置位。
- 旧 `stick-war` 的横版战斗尚未作为子模块接入；接入时只保留伤害/状态/箭矢/投射物/确定性 RNG，坐标要从一维 `x` 换成 `Vec2`，胜负条件从「雕像血量」换成城门/府衙 + 主帅状态机，矿工与宝石整条不挂载。
- 武将只有「某城守将」占位，暂无五维（统率/武力/智力/政治/忠诚）、录用/解雇、带兵上限与俘虏招降。
- 没有合击、兵种相克矩阵、训练度分段、米仓补给范围、阵法（赤火/玄水/八阵图）——这些是三国策里士气系统的核心，留到策略层第二轮。
- 没有同盟、赛季、多人、云存档；`localStorage` 也还没接，快照目前只在内存里。
- 地块产出是「按领地逐格累加」，没有名望上限、领地上限与土地开发计略。
- 战斗服/调度服是本地单进程模拟，没有服务端任务调度与幂等日志。

## 参考口径

率土之滨：225 万格土地与等级产出、连地铺路、行军时间由距离与兵种速度决定、武将兵力兼作 HP 与伤害加成、攻城值削耐久、SLG 服务端按时间队列驱动任务而非玩家即时触发（网易官方「地图玩法」「武将介绍」及 SLG 服务端架构资料）。三国策：内政/战斗两阶段、士气决定行动顺序与攻防、军粮与鼓舞影响士气、军师为辅助、兵种相克与训练度（官网「内政篇」「战争篇」「基础兵法」）。本库取两者的**结构**，不复制数值。
