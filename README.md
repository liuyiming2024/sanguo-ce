## 版本号只在一处

`src/version.js` 里的 `export const VERSION` 是**全库唯一的版本数字**（升版本只改那一行）。
升版本只改这一行，不需要批量替换、也不会漏改。

| 位置 | 以前 | 现在 |
| --- | --- | --- |
| `src/**/*.js` 的 30 处 `import ... from './x.js?v=0.9.x'` | 每次升版本批量替换 | **全部删除**。ESM 静态 import 说明符必须是字面量，塞不进变量；同源相对模块本来也不需要各自的戳 |
| `index.html` | CSS / 入口各写死一个戳 | 内联 module 读 `VERSION`，动态给 CSS 与 `main.js` 注入 `?v=${VERSION}`；HTML 里零版本字面量 |
| `config/campaign.json` / `package.json` / `assets/units/trooper.json` | 各存一份 version 字段 | **删除字段**；装配层 `boot()` 里 `cfg.meta.version = VERSION`，存档、主菜单、军令帖都读它 |
| `check-map.mjs` / `smoke.mjs` / 5 个测试 | 写死具体版本期望值 | 一律 `import { VERSION }`，只比一致性、不出现具体数字 |
| `.github/workflows/ci.yml` | 从 config 读版本再 grep | 从 `version.js` 读，并断言全库无硬编码 `?v=` 戳 |

静态自检与 CI 都会红灯拦住两件事：把版本字面量写回任何文件、或装配层忘了注入。
大版本号保持 `0`（CI 里 `case "$V" in 0.*)` 兜底）。

一个如实说的取舍：删掉子模块戳后，浏览器可能缓存旧的同名模块；纯静态 Pages
没有构建链可生成内容 hash，所以入口 HTML 与 `main.js` 仍靠 `VERSION` 加戳，
其余靠 Pages 对 HTML 的短缓存与升级时一次 `Ctrl+Shift+R`。这是无构建纯静态站点
能做到的边界，不是遗漏。

## v0.9.3：默认方阵 / 行军速度与跨步物理绑定 / 出战兵读数修正

**默认阵型改为方阵。** 用户口径：「列队不是让你列纵队啊，是让你列方阵嘛」。
`formationShape` 默认由 `line` 改为 `block`，框选一队点一个位置直接收成方阵，
不再默认拉成一长条横队；贴边 / 贴角仍按切比雪夫距离向内紧凑展开，不退化成竖条。
`formationOffsets('block')` 本身就是方形扩张（24 队实测覆盖 5×5），这轮只是把
默认项拨到它，并补静态断言防止回潮。

**「人跑太快」的根因是速度与步态脱钩，不是帧率。** 旧 `dur = 0.26 + total/420`
是魔法常数：长距离位移速度可达 695 px/s，而步态相位固定 11 rad/s（周期 0.571s）、
摆腿振幅仅约 1.56px —— 腿在原地小抖、身体在飞速平移，读起来就是「滑」和「博尔特」。
现在按跨步物理绑定：

- 步幅 = 单位宽度 `s` 的 28%（一步 0.28 身位），步频 1.75 步/秒；
- 行军速度 `unitSpeed` 由兵种 `def.speed` 归一到 4–68 px/s（重甲最慢、弓弩居中）；
- `dur = dist / unitSpeed`，相位速率 `phaseRate = 11 × (unitSpeed / 34)` 同步缩放；
- 快走快摆、慢走慢摆，跨步与平移同源，且慢速兵种不会再被同一条 tween 拖着飞。

**出战兵读数**：`bForces` 分母原用 `f.camp.length`（开战前初始编制），交战中途
阵亡后会出现「出战兵 300 / 0」这类与画面不符的读数；改为取大营存活数。

三处都只在渲染层 / 展示层，逻辑格位、命中半径、存档、命令日志、状态指纹一行未动；
相位仍只取模拟时间 `sec` + id 派生种子，隔月快进直接吸附终点。

## v0.9.2：粮草显示 / 严重时给个大概的 debuff

用户口径：「粮草显示，士气等可以在严重时给个大概的 debuff」。大版本号仍为 `0`。

### 改了什么

- **粮草常驻可见**：攻城子界面底栏左下写 `粮草 · 攻 充足 · 守 充足` 一类**短档**
  （充足 / 尚足 / 偏紧 / 将尽 / 断粮），大地图城池面板与资源顶栏仍给可管理的精确数。
  战斗层粮草不再是假的固定 100：`initialGrain()` 按「存粮够吃几旬 / 30 旬」从
  势力库存（攻方，按出征兵数扣军粮）与城存粮（守方）折算，口径与策略层
  `grainUpkeepPerUnitTurn` 一致。
- **士气等平时不摊开**：删掉底栏原来的 `士气 攻 72 / 守 72 · 矢 N`，也把
  `combatSummary`、城池面板、斥候回报里的精确士气改成「军情如常 / 军心 如常」。
  精确数值全部降级到折叠的「军情细目 · 展开」里（新增一格粮草 / 矢）。
- **严重时浮出模糊 debuff**：士气崩、断粮、疲劳、阵型溃散叠到严重档时，
  右下给一句 `军心大乱 · 战力约减三成以上，行军迟滞`。只有中文约数，
  **不含任何阿拉伯数字或小数**；朱砂只用在告急这一处，正常态无红字。
- **「大概」不骗人**：`condition.js` 的 `moraleFactor / fatigueFactor /
  formationFactor / hungerFactor / marchFactor` 就是 `damageOf()` 与 `moveToward()`
  真正乘上去的系数。档位由同一份系数相对「正常状态」的下降量派生，
  不是 UI 另写一套公式。断粮真实降低伤害、拖慢行军、压住士气恢复
  （`grainDrainPerSec` 从 0.01 降到 0.004，断粮是久攻不下的结果而非开局常态）。
- **斥候探不到粮仓**：情报对象没有 `grain` 字段，`cityCondition` 加
  `grainKnown:false`，否则缺失字段会被当成断粮、所有情报都误报告急。

### 顺带：方向中轴线 / 整圈 360°（上一条口径的架构校验）

- 「改方向中轴线不能变」：八向帧共用 `footY=780` 脚底中心基线、统一 560×820
  画布；渲染层所有帧的落点恒为 `-w/2, -dh`，地面投影画在斜轴变换之前、用不变的
  `o.x`，斜轴 `GROUND_SHEAR=-0.17` 是全帧共用常量。转身靠换帧，**不靠 `rotate`
  整张图，也不按方向帧改 dx**。静态断言与单测守死这条。
- 「360 旋转」：`dirIndex()` 覆盖 `[0,2π)` 全圈、负角与超圈角度规整、0 与 360°
  同帧、八个扇区各不重复。修了一个真问题：`atan2` 在精确扇区边界带 1e-15 误差，
  直接 `floor` 会让同一个 202.5° 一会儿落第 4 帧一会儿落第 5 帧 —— 整圈转身时
  看着像突然跳帧。现在把几乎整数的商吸附到整数，边界确定归入后一扇区。
- 边界如实说：仍是 **8 张离散帧量化到最近邻**，不是 16/32 向连续插值；
  要更细的转身得再出一批素材，按分工不在这轮铺开。

## v0.9.0：自检背面 / 队伍感 / 框选自动列队 / 走路相位

用户验收后提了三条：「**右后 135° 身体没转过去，自检一下**」「**人太散了，他毕竟是队伍……框选一些人，点击一个位置让他走过去，然后自动列队**」「**他要走路啊，所以还需要更多**」。

### ① 自检：三张背面其实是假的

逐张放大核对躯干后确认，比点名的那张还多一处：

| 帧 | 旧版问题 |
| --- | --- |
| `d3_back_right` 135° | 明显是正面偏一点：护心镜、腰前蝴蝶结、盾面木板铆钉全在，只是把脸罩住 |
| `d4_back` 180° | 同样是正面截掉脸，不是背对观者 |
| `d5_back_left` 225° | 半对，肩带方向勉强，躯干仍偏正面 |

根因不是提示词写得不够，而是 **AI 逐张生图做不了可靠的 3D 旋转**——它把「背面」理解成「正面把头盔拉下来」。重画这三张时改用了**可见结构硬标准**而不是角度词：绝对看不到脸 / 护心镜 / 腰前蝴蝶结 / 盾面铆钉，必须看到背带、背甲横道、盾背握把与背带。三张都通过人工验收，对照图见 `背面三帧修复对照.png`。

为了防止以后误把旧图放回仓库：8 张源图收进 `assets/units/src/`，`scripts/build_units.py` 可一键复现全部产物，`trooper.json` 记下每张源图的 sha256，静态自检逐张校验，不一致就红灯。另外清掉了正背帧脚下一片 AI 画出来的浅青白碎斑（定点判据：偏青绿 + 浅亮 + 低饱和，米黄靴描边不受影响）。

### ② 队伍感：不再各朝各的

之前静止时用 id 派生偏角覆盖八向，看起来像散兵游勇。现在**同区同向、两军相向**：大营一律朝城内（右 90°），城内一律朝城门（左 270°）；行军时按位移方向换帧，走完自动归队，不保留上次的朝向。整队一眼是队伍。

### ③ 框选 → 点一个位置 → 自动列队

`src/formation.js` 是纯逻辑层（不碰 DOM / 墙钟 / 随机源，可进单测与重放）：

- 三种阵型 **横队 / 方阵 / 楔形**，小地图 HUD 右上角点一下循环切换；
- 以点击格为中心生成槽位，按「离目标近的站前排 + id」确定性排序；
- 自动剔除越界格、已占用格，不让两队叠在一格；贴边 / 贴角目标向内收；
- 结果逐队写回 `deployUnit`，渲染层的 `motion` 自动接住逻辑格位变化，产生行军 tween；
- 点在城外大营 = 整队撤回。

手势仲裁：短拖画圆框选 → 单击目标点 = 编队移动；框选后再拖出向量仍是定向齐射；单击单位仍是单兵接管。命中单位永远优先于 HUD 热区。

### ④ 走路：8 向 × 3 相位 = 24 帧

`scripts/build_units.py` 从已验收的 idle 帧**确定性派生**步态帧：上半身完全不动，腰以下按 `tanh` 左右腿反向迈出 + 抬脚，脚底加两粒淡墨扬尘，用最近邻重采样不做任何模糊。_idle / 左步 / 右步_ 三态打包成 `trooper-sheet.png`（8 帧）与 `trooper-walk-sheet.png`（16 帧），运行时按 `sin(phase)` 符号在左右步之间交替。

没有让 AI 逐张画腿——那会画出多腿、甲片漂移，也会破坏「同一个人」的确定性。24 帧 + 2 sheet 共 26 张 PNG，manifest 记明相位规则；无墙钟、无 `Math.random`，同一 `sec + heading + phase` 逐像素一致，隔月快进不受影响。

### 顺手修掉的两个真问题

- **单击被误判成拖动部署 / 漏选**：竖屏地址栏收起会让 canvas `rect` 在按下与抬起之间漂移，原来用两套坐标系算 `dist`，单击被当成拖拽；`hitUnit` 只在按下时做一次，抬起时布局变了就漏选。现在手势位移一律用 `clientX/clientY`，部署落点取实时 rect，抬起时补一次命中测试。同时把「框选一队」与「单兵接管」分开：单兵状态下单击仍是选人，只有框选后单击才编队。连跑五轮烟测不再偶发。
- **静态自检的失败退出排在新增断言之前**：v0.8.0 追加的那批断言其实一直没真正生效（失败也打印全绿）。已把 `process.exit(1)` 统一移到文件末尾，第一次跑就暴露并修掉了两条过时断言。

### 边界（如实说）

- 编队移动目前是**目标格部署 + 直线 tween**，不是城内网格 A* 绕障碍寻路；真实战斗结算（伤害、投射物、士气溃散、擒主帅）仍未接，寻路要跟它一起做。
- 器械（床弩 / 抛石机）仍是程序化俯视木架，没有八向位图；其余兵种同理。
- 八向素材是**站立 3/4 转身**，不是 58° 斜俯视几何投影；纵向压缩只表达「站在地面平面上」。
- 步态是几何派生的腿部错位，不是手绘逐帧动画；`s≈20` 桌面档够用，`s≈10` 手机档仍是轮廓级。

**验证**：100 单测（新增 `formation.test.mjs` 12 项：三种阵型、贴边贴角、占用格避让、确定性、撤回、朝向、24 帧差异、源图 hash 锁）、138 项烟测（队伍同向、步态换帧、三阵型、真实鼠标框选→点击→列队）、静态自检（失败真退出）全绿。

## v0.7.4：斜俯视 —— 人物不再贴一张正侧面证件照

用户点破的透视错位：「**你这个是俯视视角啊，就算我是俯视，你也不应该是一个正侧面的视角**……我是说你这个人物」。之前 v0.7.3 把甲片做精了，但画的是**正面/正侧面站立的全身立绘**，贴在俯视战场上像证件照，且冷灰铁 + 对称构图读着不像中国的，20px 以下细节又糊成一团（「适量度」）。

这轮先出一张**斜俯视造型参考板**（`shots/ref-topdown.png`），再把造型法则转写成 canvas 路径 —— 参考图仍只做造型依据，**没有作为位图贴进游戏**，`soldier.js` 里没有 `drawImage` / `new Image`。

**透视**：俯角约 58°（不是西式 30° 等距棋盘），用中国界画「顶面 + 侧面 + 地面投影」三层表达高度 —— 顶面亮、侧面用 `lip()` 补一道暗厚度、脚下扁椭圆投影。`VIEW = {cos:0.53, sin:0.85}`。近大远小很弱，散点式。

**人形**：看见的是**兜鍪顶（菱形 + 盔脊）**、两侧斜展的肩甲、被压缩成短梯形的躯干、斜置可见盾面与厚度的矩形木盾；**脸完全不可见** —— 没有眼缝、没有肤色、没有五官，只留盔檐下一道暗影。兵器落在**地面平面内**的一道斜线 + 一截抬起的柄，不是竖在身侧的道具。整体带 -17° 斜轴，破掉「正面印章」的对称。

**器械**：床弩是斜向长梁 + 榫卯横销 + 四个扁椭圆轮 + 地平面内 V 张的双弩臂 + 绞盘顶面 + 中轴长矢；抛石机是 A 架俯视投影 + 斜臂 + 配重箱顶面 + 吊索石弹。操作兵只是极小的俯视菱形比例尺。俯视下圆变椭圆，`wheelTop()` 里的辐条随行军旋转。

**中式**：色板从冷灰铁改**墨青（花青）+ 赭石木 + 墨线**，木梁交接画榫卯短销，硬边平涂、无发光无渐变，取汉画像石拓片 / 界画舆图的语汇。

**适量度（按尺度换笔画，不是把大图缩小）**：
- `k = s / 17` 按俯视压缩后的 13k 归一 —— 初版沿用 `s/26`，手机 s=10.4 的单位只有 5px 高，再极简也读不出。
- `s < 13` 走 `drawTiny()`：只画兜鍪顶 + 两肩 + 短躯干 + 一根兵器（器械是斜梁 + 两轮 + 一臂），不画甲片横弧 / 护心镜 / 顿项 / 靴 / 榫卯 / 辐条 / 操作兵。
- 桌面档甲片横弧 3 道 → 手机 1 道；扬尘只在真行军时 2 点；满血不画血条。

**行军动画**：部署不再是「啪一下瞬移」。`city-view` 私有 `motion` 表每帧比对逻辑格位，
发现变化就开一段 tween（smoothstep，`dur` 随距离 0.30–0.95 模拟秒），从旧点走到新点：

- 拖动时士兵**跟着手指走**；松手位置作为 tween 起点，从手指处走回目标格。
- 摆腿 / 摆臂 / 躯干起伏 / 前倾 / 披风与盔缨飘动 / 脚下扬尘，相位 = `(sec - startSec) × 步频 + idSeed(id)`。
- 起步收步用 `sin(πt)` 包络，停下回到极轻的待机呼吸。
- 相位只取 `sec`（战斗时刻＝模拟时间）+ 由 id 派生的静态种子：**同 sec 逐像素一致**；
  暂停 / 退出时 sec 冻结，动画一起冻结；隔一个月再点进来 sec 跳变远超 `dur`，**直接吸附终点**，
  不补跑一段没人看见的行军。
- `motion / lastKey / lastXY / dragPos` 全是渲染层闭包私有，不写 `state`、不进存档 /
  命令日志 / 状态指纹 / 军令帖；离开期间的援军仍由策略层按 id 合并，不受影响。

**顺手修了一个会直接杀死动画的真 bug**：`#cityCanvas` 有 1px 边框，
`clientWidth` 恒比 `rect.width` 小 2px，原先 `>1` 的自愈判定让 `resize()` **每帧执行**，
而 `resize()` 会清掉 `motion` —— 行军永远开不起来。现在只有 W/H 真变了才清，
自愈只补 `attr` 尺寸。

**验证**：124 项烟测（新增 7 项：部署开 tween、中间帧落在起终点之间、同 sec 逐像素一致、
跳到终点吸附、动画不污染 state、拖拽跟手、零 JS 报错）、81 单测、静态自检全绿。
静态断言守死：无随机源 / 墙钟、七兵种分支齐全、`if (changed)` 才清 motion、相位只取 sec。

**顺带修了验证链路本身的假绿**：`scripts/check-map.mjs` 的 `ok()` 一直只把失败 push 进数组，
末尾却无条件打印「全绿」、从不 `process.exit(1)` —— 前几轮报的「静态自检全绿」其实不可信。
这轮补上失败退出，并修正 6 条随实现演进而过时的断言（纸页点名阈值、文武底色用 `dataset.tone`、
缩略图实底按风格选色、山体分染收敛为 `azur`、draw 自愈表达式、兵种分支按 `proj/type` 判定）。
现在 CI 里任何一条不成立都会真的红灯。

**没动**：`gongbi.js` 画风、UI 墨底印玺皮、移动端适配、24×16 逻辑网格与部署存档、

## v0.7.1：移动端竖屏点击适配（本轮不改画风）

用户实拍反馈：**移动端竖版「点的位置和实际位置不匹配」**。这轮只修适配，

实测复现（390×844 / DPR 3 与 360×780 / DPR 2，真触屏 context）：
桌面点第一个兵命中 `u1`，竖屏却稳定命中 `u2`。**坐标映射本身是准的**
（`local=[124,175]` 精确等于 `u1.unitXY`），错位来自三处：

| 根因 | 后果 |
| --- | --- |
| 竖屏 `cell=10.8px`，而 `hitUnit` 半径固定 15px、单位图标 20px，且**倒序返回第一个命中** | 相邻单位重叠，点 A 必选到 B |

| 抬起时用 **down 时缓存的 rect**；iOS 地址栏收起只改 `visualViewport`，常不触发 `window.resize` | 真机上系统性偏移 |

**改动**

- canvas 属性尺寸严格等于 `CSS 尺寸 × DPR`，不再钳制/兜底；首次布局拿到 0 尺寸时不重建（避免位图被压成 0×0）。
- `hitUnit` 改取**距离最近**的单位，半径 `min(unitPx*0.75, cell*0.48)`，不超过半格。
- 竖屏（`W<560`）收窄左侧大营（0.22→0.14）、camp 改 2 列、图标随 cell 缩放，24 列城内网格 `cell` 从 10.8 提到 12.7。
- 大地图与小地图**全程用相对 canvas 的 local CSS 坐标**（down/move/up 统一），抬起取实时 rect，不再缓存。
- 加 `visualViewport.resize/scroll` + `orientationchange` 监听；并在两次 `draw()` 内用 `clientWidth` 做轻量自愈——事件没送达也不会错位。
- 重置离屏上下文基线（`lineCap/alpha/dash/…`），修好 `gongbi→jiehua→gongbi` 无法逐像素复原的 A/B 回归。

**验证**：117 项烟测（新增 6 项移动端真触屏断言：位图尺寸一致、点城池、缩放后命中、点兵不串到邻居、拖放落点等于视觉格、rect 偏移后仍命中）、81 单测、静态自检全绿。
另在烟测里修了一个测试夹具问题：授简层是异步 `start()` 的，过早 `hide()` 会被随后的 `render()` 重新显示，简卡会吃掉地图点击 —— 现在等简卡出现再跳过。

**没动**：工笔画风（`gongbi.js`）、UI 墨底印玺皮、24×16 逻辑网格与部署存档、城内真实战斗结算。

## v0.5.0：行台授简 / 审美收尾（留白与读图）

### 1. 新手引导：行台授简十二简

不是一张静态玩法面板，是**跟着真实动作走的十二枚简**：受檄入局 → 观军历 → 读纪事 → 观舆图 → 相地块 → 下军令 → 推军历 → 在途军情 → 入城布阵 → 调兵与单兵 → 两端并行 → 合卷自行。每简有叙事、史注引文、聚焦目标与一句「去做什么」。

- **事件驱动**：第三简等 `tab:story`、第四简等 `mapPanned`、第五简等 `tileSelected`、第六简等 `orderIssued`、第七简等 `turnAdvanced`、第八简等 `orderPanelOpened`、第九简等 `battleOpened`、第十一简等 `battleClosed`。事件只认当前那一简，纯阅读简不吃事件，乱点不会跳简。
- **不锁死**：遮罩与高亮框 `pointer-events:none`，只有简卡吃指针——被引导的「拖地图 / 点地块」是真的能操作。每一步也都能手动「下一简」，不做强制卡关。四条退路：上一简 / 跳过 / Esc 暂收 / 合卷。
- **不盖 Tab**：简卡定位避开底栏（沿用 v0.4 的 `#screen{bottom:58px}`），引导期间 11 个入口照常可点。
- **边界**：引导是**本机界面状态**，独立 `localStorage` key，不进 `campaign state`、不进 `commandLog`、不进 `stateFingerprint`、不进军令帖——导入对方存档不会继承对方看过几简，联机重放也不受污染。刷新后按进度续播；已完成/已跳过不重播；系统页「重看行台授简」可从头再来。
- 状态机 `src/tutorial.js` 是纯逻辑（可序列化、可重放），DOM 只在 `src/tutorial-ui.js`；`config/tutorial.json` 存全部文案，改字不碰代码。

## v0.2.0：清晰度 / 指令层 / 城池布阵

### 0. 两个界面，职责严格分开

| | 大地图 (`map-render.js`) | 城池小地图 (`city-view.js`) |
| --- | --- | --- |
| 视口 | 可拖动、可缩放、`全图`、右下角缩略导航 | **固定视口，一屏放下 24×16 城内网格；不拖动、不缩放** |
| 交互 | 只**下指令**（12 类，全部带 `arriveTurn`） | 只**调兵**：拖拽把单位在「城外大营 ↔ 城内」之间部署；圆框选 + 二次拖拽定方向；单击单兵接管 |
| 绘制 | 地貌离屏预渲染，信息层屏幕空间 | 全部主画布按屏幕像素绘制 |

### 清晰度为先

`tilePx` 12 → **24**，离屏位图 `3456×2592`。更关键的是分层：**城名、山水注记、关隘名、土地等级、图廓、比例尺全部移到屏幕空间绘制**，字号/线宽按 `1/camera.scale` 换算，永远是固定物理像素，不随缩放被插值糊掉。山形/树冠/河纹/官道线宽与对比度同步提高；接近 1:1 才用高质量插值，缩到很小时用最近邻保住细线。

### 大地图不止「占领地块」

`claim / march / scout / develop / buildFort / transfer / garrison / withdraw / recruit / fireDirectional / stratagem / reinforce` 共 12 类，配置与指令层一一接线：

- **屯田**：己方地块 `level+1`，重算四资源产出
- **筑垒**：己方地块生成垒寨、通行代价下降
- **侦察**：写 `intel` 情报（守军/城防/士气/归属），不改兵力、不开战
- **调动 / 驻守**：只对己方城；**出征 / 增援**：只对敌方城
- **撤兵**：从敌城大营收兵回出发城；**撤令**：退还尚未出发的兵员与已扣资源
- 资源池是**可花费的累积库存**，与「每旬流量」分离（`state.resources` vs `state.yield`）
- 「在途军情」面板列出所有命令、预计抵达旬、路径格数，可逐条撤令

### 己方在城内，敌方在城外扎营

`campaign.forces[cityId] = { inside, camp }`，每个元素是独立实体（id / 兵种 / 阵营 / hp / 格位 / 人数 / 选中态）：

- 开局各城守军展开为**城内**实体
- 抵达**己方**城 → 新部队进 `inside`（布防）
- 抵达**敌方**城 → 新部队进 `camp`（**城外扎营**），城内是守军
- 小地图把 `camp` 里的兵**拖进城里 = 派人进去打**，拖回 `camp` = 撤出；这就是「先打着、后续投入、中途退出」的落点

### 两端并行的架构级约束

退出子界面拍快照时**深拷贝 `forces`**；恢复时按 **unit id 合并**，不是无条件覆盖 —— 否则离开期间策略层并行抵达的援军会被旧快照冲掉，直接违反「两端并行」。同时把 `createCityView` 改成**单例 + `AbortController` 一次性绑定**，切换城池只换 `getCityId()`，避免重复监听导致一次拖拽触发多次部署。

### 2. 率土之滨式的地块规则

| 机制 | 实现 |
| --- | --- |
| 土地等级 1–9 | 按高程、林地、距城加成推导，缩放足够时显示角标 |
| 四资源时产 | 木/石/铁/粮按 `base × level` 逐格累加到势力资源池 |
| 连地铺路 | 目标格 8 邻域内必须有己方领地才能出征，`claim` 命令逐格推进 |

### 3. 三国策式的策略层

- **内政/回合**：1 回合 = 1 旬（建安五年二月上旬起），人口增长、粮草收支、募兵、城防修复、疲劳恢复。
- **隐藏属性**（早期为全隐藏，现行口径见 v0.9.2）：士气 / 疲劳 / 警觉 / 阵型完整度不摊开精确数值，只通过溃散、被擒、征兵上限、行军速度间接生效；粮草改为常驻大概档位，严重时才给模糊 debuff。对齐三国策「士气决定行动顺序与攻防倍率、粮尽则士气掉」的思路。
- **军师是辅助**：`junshi` 零伤害、无投射物，只有鼓舞/疑兵/火攻计策槽。**没有巫师、巨人、矿工、法球、召唤、眩晕**——三国背景里这些东西违和。
- **兵种**：刀盾、长枪、弓弩、床弩、抛石机、重甲步、军师。所有 `projectile != null` 的远程单位都能吃「圆框选 → 二次拖拽定方向」的齐射指令，不只弓手。
- **单方但可任选**：开局选曹操 / 袁绍 / 刘备，其余势力由 AI 每两旬决策（优先铺路，其次出征），确定性 RNG。

### 4. 两端并行，不是冻结

这是最容易写错的一条。战斗层**不是一直空转的后台进程**：

```
enter(snapshot, nowTurn) → 用同一个 advanceBattleStep() 固定步长空跑到 nowTurn
                         → 接上 rAF 实时循环
leave()                 → 拍 BattleSnapshot { sec, campaignTurn, rngSnapshot,
                                              pendingOrders, morale, cityWall, ... }
                         → 战斗层完全停跑；策略日历照常走
```

- 「隔一个月再点进去」**不另写解析结算公式**，而是拿同一份纯逻辑以 1/60 秒无渲染空跑几千步（毫秒级）。因此「一直盯着打」和「离开再回来」结果**必然一致**——单测逐字段比对 `sec / stepsRun / morale / cityWall / pendingOrders`。
- 邮箱事件带 `atSec` 时间戳，按**整数步索引**回放，不是月末一次性倾倒。既避免 `1/60` 累加 480 次后的浮点漏判，也避免放宽容差导致的重复消费。
- `rngSnapshot` 可序列化，快进后随机序列不分叉。
- 终局回写以 `battleEndTurn` 为准，**绝不回退到开战那一回合**；城池易主时同步栅格归属，地图颜色与策略状态不分叉。

### 5. 画风与交互

- 拖动 >140px 平移地图、短拖画圆框选、单击看格详情、双指/滚轮/`＋−` 缩放、回中。
- 每个能进的层都有醒目 `×`：`Esc` 分级 `玩法 → 战场 → 信息卡`。窄屏信息卡变底部抽屉。
- 顶栏实时显示日期、势力、四资源与已占领地块数；信息卡给地形、等级、四资源时产、通行代价、归属。

## 已知限制（下一轮接）

> **下面这些是边界，不是待修的 bug**；README 各版本段里的「验证 N 项 / 边界」也是当时快照，
> 按各自版本读，别抄进当前清单。当前实数见顶部「当前验证实数」。

- **八向是 8 张离散帧最近邻量化，不是连续插值**；仍是站立 3/4 转身，不是 58° 斜俯视几何投影。
- **步态是 `build_units.py` 几何派生**（上半身不动、`tanh` 反向迈腿），不是手绘逐帧；
  缩放 `s<13` 走 `drawTiny()` 轮廓档，不加载 PNG。
- **器械八向是刚体旋转投影**；城内 8 向 A\* 绕障已在 v0.9.1 接上，
  v0.9.0 段里「编队是直线 tween、不是 A\*」是当时的边界，不是现状。
- **纯静态 Pages 无构建链**：入口 HTML + `main.js` 靠 `VERSION` 加戳，其余靠短缓存 +
  升级时一次 `Ctrl+Shift+R`。这是能做到的边界，不是遗漏。
- **`supabase/` 是「零预算联机地基」**，和本机三席存档是两条线，别混读。
- **小程序「最小可玩切片」不是两端跑**：`miniprogram/logic/` 只是纯逻辑层镜像，
  皮（WXML/WXSS/Canvas DPR/touch 命中）、位图分包、真机 ESM 转译都未启动；
  切片页只验「逻辑层能跑、能读档、能推旬」+ 零位图格网。详见 `docs/小程序军令帖验证说明.md` §十.6。
- **P4 真分包未启动**：`app.json` 没有声明 `subpackages`。PNG 原样分包会失败（3 张各自超 2 MB），
  但压缩方案已实测：webp 后 2.59 MiB 分两组各 ≤ 2 MB。仍不启用的原因是 **webp 在小程序端的
  解码支持与端侧皮重写未真机验证**，且空分包会报错；模板与一键脚本已给，等真机 `assets:build`
  后并入。10 张源底稿 JPG（B5 待溯源）与 48 张单帧 PNG 明确不进包。
- **画布页不是两端跑**：`pages/canvas/` 只用 `applyDrawOps` 画逻辑层降采样格网，没有战场、
  没有位图立绘、没有 `soldier.js`；真机 canvas 2d 节点与 DPR 行为未验，拿不到节点会如实降级。
- **可交互格网不是可交互舆图**：视口与命中作用在 18×14 态势缩略上，每格约 8×8 源格；
  双指手势只做了最朴素的增量平移，真机 touch 序列、惯性、阻尼未验。
- **舆图不是位图**：`guandu.js` / `atlas.js` 是程序化离屏画布，仓库里没有 `bg+fg` 图片文件，
  清单里「按章分包两张舆图」是旧口径，别再照抄。
- **长局系数未由真人试玩定稿**：0.035 / 0.07 / 1.0 / 0.6 这组由 200 旬 × 5 seed
  长局对演 + 4 策略 × 2 seed 对演定标，证明「玩家作为 / 不作为」走出不同曲线，
  但仍未做真人连续 100 旬以上对局；AI 无同盟 / 外交 / 多目标协同，只到「可预测但有变数」。
- **不动作时没有自然终局**：无人值守战斗简算让战线真的推进（200 旬 9:3 → 7:5 / 6:6 / 4:8，
  500 旬到 3:9），但玩家什么都不做时 AI 会因局部饥荒收敛，不会自动把玩家全灭；
  终局三态由 `src/outcome.js` 判定、在构造场景与主动对局中可达，不是长局必然结局。
- **简算是策略层军情，不是逐帧攻城**：复用士气 / 疲劳 / 阵型 / 断粮四系数与 ±15% 扰动，
  不产生 mailbox / atSec、不进战斗层快照；玩家亲率的战斗仍全部进子界面手打。

- **旧 `stick-war` 横版战斗仍未挂为本库子模块**。本库攻城战是自己的纯逻辑层，
  没有复用旧横版代码；接入时只保留伤害 / 状态 / 箭矢 / 投射物 / 确定性 RNG，
  坐标从一维 `x` 换 `Vec2`，胜负从「雕像血量」换成城门 / 府衙 + 主帅状态机，
  矿工与宝石整条不挂载。
- **单位之间没有连续体推挤**：编队按格占用避让，投射物命中用格半径判定，
  不是逐像素弹道；城内网格没有高度差与楼层。
- **没有合击、兵种相克矩阵、训练度分段、米仓补给范围、阵法**（赤火 / 玄水 /
  八阵图）。军师只有鼓舞 / 疑兵 / 火攻三种，且只改隐藏属性与城防。
- **武将五维已进战斗数值，但没有录用 / 解雇 / 招降界面**；名将只在配置表里，
  俘虏登记后不触发招降对话。设施等级已进产出 / 征兵上限 / 城防初始值，
  但**尚未接进行军速度**。
- **素材是站立 3/4 转身的写实淡彩位图，不是 58° 几何俯视投影**：做了纵向压缩
  与地面斜轴，但俯视下看不到正脸属于几何事实；桌面 `s≈20` 时甲片细节读不出，
  靠手机 tiny 轮廓帧与原分辨率放大结构图验收。画风本身按分工交给另一边。
- **双指捏合已在装配层实现**，真机多点触控与惯性 fling 未做（无真机环境）；
  镜头变换仍是瞬跳，没有缓动。
- **章回史实事件是入场触发**，不是逐帧战斗推演；抉择的 effect 已作用于城防 /
  士气 / 情报 / 资源。
- **引导事件驱动**依赖装配层在对应动作处发出 `tutNotify`；新增动作需同时改
  `config/tutorial.json` 的 `await` 与 `main.js` 接线，静态自检核对一一对应。
- **联机仍是本机存档 + 军令帖手动交换**：`src/save-slots.js` 已有甲乙丙三席与坏档回退，
  但仍没有账号、云同步、服务器权威时间；跨设备实时房间属需常驻服务的范围。
  `supabase/` 是零预算联机地基，与本机三席存档是两条线，别混读。
- **地块产出按领地逐格累加**，没有名望上限、领地上限与土地开发计略。
- **粮草 debuff 只到阵营级**：城内单位共享一方粮草档位，没有逐队辎重、
  截粮道、火攻烧仓等更细的后勤玩法；档位是 5 级短档，不是连续数值。
  策略层另有**城仓断粮**（`src/economy.js`）：掉军心 / 逃兵 / 锁征发，并按 `starvingYield`
  给所辖地块减产；AI 滞留战斗另由 `src/field-resolve.js` 简算回写，所以长局城数会变、
  领地与产量随战线收缩。逐帧攻城仍在子界面，见旬循环说明 §十一。
