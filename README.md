## v0.7.3：去呆萌 —— 器械为主体、遮面甲士、肃杀剪影

用户反馈「太呆萌」，并点破根因：**「叫你床弩你主体应该是一个弩啊」**——
之前七个兵种全画成「一个人举着一件小道具」，人形 + 圆脸 + 亮肤色 + 粗圆线 + 短粗比例，
再精致的甲片也救不回来。这轮用 AI 生成**造型参考板**（`shots/ref-sheet.png`
/`ref-trooper.png`，汉末军械与甲士设定），再把造型法则**转写成 canvas 路径**——
参考图只做造型依据，**没有作为位图贴进游戏**：`soldier.js` 里没有 `drawImage`、
`new Image`，仓库仍保持零位图、确定性 hash、同 sec 逐像素一致。

参考板给的六条规矩逐条落地：

1. **器械为主体**：床弩 = 带轮木架巨弩（底座、A 形支架、双弩臂、弦、长矢、绞盘、
   两个辐条轮），抛石机 = 斜臂配重投石机（配重箱、吊索、石弹、带轮底座）。
   两具军械旁只留一个约 1/4 高的墨甲操作兵作比例尺，不再是人举着小弩/小石头。
2. **人不露脸**：兜鍪压到眉、顿项护颊、面甲罩住整张脸，只留一道极细冷光眼缝；
   全程无肤色、无眼鼻嘴、无圆脑袋。
3. **比例拉长**：七头身，窄肩收腰长腿，`k = s/26` 让 20px 的兵是细长剪影而非短粗小人。
4. **札甲细密横道、素铁护心镜、战裙至膝、胫甲黑靴、矩形木盾、环首直刀**。
   盾从圆改矩形，护心镜从菱格纹布改素铁方片，去掉盔缨天线。
5. **冷铁灰 + 赭褐木 + 墨黑三层**，暗部占七成，只有轮廓一道冷光；阵营色缩到
   盾边 / 胸纹 / 弩身一道细线。满血**不画亮绿血条**（只在掉血或选中时浮出暗条）——
   那条绿线是默认画面里最跳的「游戏 UI」感来源。
6. **器械不摆腿**：`unitKind()` 把床弩/抛石机判为 `engine`，行军只转轮 + 颠簸 +
   斜臂微摆 + 轮后扬尘；人形才摆腿，且幅度从 3.6k 收到 1.5k，不蹦跳。

`city-view.js` 只改了 import 与暴露 `unitKind`，行军 tween、拖拽跟手、快照/快进、
移动端适配、24×16 逻辑网格与部署存档一行没动。

**验证**：128 项烟测（新增 4 项像素级断言：`unitKind` 分派、军械横向跨度显著大于人形、
满血绿色像素为 0 且掉血才浮条、器械静止与行军逐像素不同）、81 单测、静态自检全绿。
静态断言守死：无位图/墙钟/随机源、面甲遮脸且无肤色、矩形木盾、无盔缨、
器械 `!engine` 才摆腿、满血条件画血条。

**没动**：`gongbi.js` 画风（交给另一边）、UI 墨底印玺皮、移动端点击适配、
城内真实战斗结算（伤害 / 投射物 / 士气溃散 / 擒主帅）。

## v0.7.2：士兵精细重绘 + 行军移动动画

这轮只做这一件事。`src/soldier.js` 是新增的**纯绘制模块**（无 DOM、无 state、
无墙钟、无 `Math.random`），`city-view.js` 只负责「从哪走到哪」。

**立绘**：从「粗描边 + 阵营色芯」的火柴人换成汉末甲胄 —— 札甲甲片横道与纵缝、
护心镜、护肩、腰带垂带、战裙褶、兜鍪顿项 / 眉庇 / 护鼻、盔缨、靴与护腕。
军师改纶巾 + 羽扇（仍是零伤害辅助）。七个兵种各有独立兵器剪影：环首刀盾 /
长枪红缨 / 弓弩 / 床弩 / 抛石机 / 重甲大盾短槌 / 羽扇竹简。
阵营色只留在盔缨、胸纹、盾心、披风里衬；主体是压灰的冷铁与赭革，没有亮金正红。
按 `s` 分三档：桌面 `s≈20` 画全甲片，手机 `s≈10` 自动降档但保留轮廓、甲色与兵器。
底色被工笔色板换成浅绢后冷灰甲会融进地面，所以按 `cityFloor` 明度自动切两套设色
（浅纸底→墨绿札甲 + 石绿高光；墨底→冷灰铁甲 + 亮高光），画风那边改回深色会自动换回来。

**行军动画**：部署不再是「啪一下瞬移」。`city-view` 私有 `motion` 表每帧比对逻辑格位，
发现变化就开一段 tween（smoothstep，`dur` 随距离 0.30–0.95 模拟秒），从旧点走到新点：

- 拖动时士兵**跟着手指走**；松手位置作为 tween 起点，从手指处走回目标格。
- 摆腿 / 摆臂 / 躯干起伏 / 前倾 / 披风与盔缨飘动 / 脚下扬尘，相位 = `(sec - startSec) × 步频 + idSeed(id)`。
- 起步收步用 `sin(πt)` 包络，停下回到极轻的待机呼吸。
- 相位只取 `sec`（战斗时刻＝模拟时间）+ 由 id 派生的静态种子：**同 sec 逐像素一致**；
  暂停 / 退出时 sec 冻结，动画一起冻结；隔一个月再点进来 sec 跳变远超 `dur`，**直接吸附终点**，
  不补跑一段没人看见的行军。
- `motion / lastKey / lastXY / dragPos` 全是渲染层闭包私有，不写 `state`、不进存档 /
  命令日志 / 状态指纹 / 军令帖；离开期间的援军仍由策略层按 id 合并，不受影响。

**顺手修了一个会直接杀死动画的真 bug**：`#cityCanvas` 有 1px 边框，
`clientWidth` 恒比 `rect.width` 小 2px，原先 `>1` 的自愈判定让 `resize()` **每帧执行**，
而 `resize()` 会清掉 `motion` —— 行军永远开不起来。现在只有 W/H 真变了才清，
自愈只补 `attr` 尺寸。

**验证**：124 项烟测（新增 7 项：部署开 tween、中间帧落在起终点之间、同 sec 逐像素一致、
跳到终点吸附、动画不污染 state、拖拽跟手、零 JS 报错）、81 单测、静态自检全绿。
静态断言守死：无随机源 / 墙钟、七兵种分支齐全、`if (changed)` 才清 motion、相位只取 sec。

**顺带修了验证链路本身的假绿**：`scripts/check-map.mjs` 的 `ok()` 一直只把失败 push 进数组，
末尾却无条件打印「全绿」、从不 `process.exit(1)` —— 前几轮报的「静态自检全绿」其实不可信。
这轮补上失败退出，并修正 6 条随实现演进而过时的断言（纸页点名阈值、文武底色用 `dataset.tone`、
缩略图实底按风格选色、山体分染收敛为 `azur`、draw 自愈表达式、兵种分支按 `proj/type` 判定）。
现在 CI 里任何一条不成立都会真的红灯。

**没动**：`gongbi.js` 画风、UI 墨底印玺皮、移动端适配、24×16 逻辑网格与部署存档、
城内真实战斗结算（伤害 / 投射物 / 士气溃散 / 擒主帅）。

## v0.7.1：移动端竖屏点击适配（本轮不改画风）

用户实拍反馈：**移动端竖版「点的位置和实际位置不匹配」**。这轮只修适配，
`gongbi.js` 一行未动（画风按分工交给另一边继续）。

实测复现（390×844 / DPR 3 与 360×780 / DPR 2，真触屏 context）：
桌面点第一个兵命中 `u1`，竖屏却稳定命中 `u2`。**坐标映射本身是准的**
（`local=[124,175]` 精确等于 `u1.unitXY`），错位来自三处：

| 根因 | 后果 |
| --- | --- |
| 竖屏 `cell=10.8px`，而 `hitUnit` 半径固定 15px、单位图标 20px，且**倒序返回第一个命中** | 相邻单位重叠，点 A 必选到 B |
| `cityView.resize()` 把 rect 钳到 `Math.max(320/260, …)`；`mapRenderer.resize()` 用 `rect.width \|\| 800` 兜底 | 位图被浏览器拉伸，`local()` 的 CSS 坐标与画面分家 |
| 抬起时用 **down 时缓存的 rect**；iOS 地址栏收起只改 `visualViewport`，常不触发 `window.resize` | 真机上系统性偏移 |

**改动**

- canvas 属性尺寸严格等于 `CSS 尺寸 × DPR`，不再钳制/兜底；首次布局拿到 0 尺寸时不重建（避免位图被压成 0×0）。
- `hitUnit` 改取**距离最近**的单位，半径 `min(unitPx*0.75, cell*0.48)`，不超过半格。
- 竖屏（`W<560`）收窄左侧大营（0.22→0.14）、camp 改 2 列、图标随 cell 缩放，24 列城内网格 `cell` 从 10.8 提到 12.7。
- 大地图与小地图**全程用相对 canvas 的 local CSS 坐标**（down/move/up 统一），抬起取实时 rect，不再缓存。
- 加 `visualViewport.resize/scroll` + `orientationchange` 监听；并在两次 `draw()` 内用 `clientWidth` 做轻量自愈——事件没送达也不会错位。
- 重置离屏上下文基线（`lineCap/alpha/dash/…`），修好 `gongbi→jiehua→gongbi` 无法逐像素复原的 A/B 回归。

**验证**：117 项烟测（新增 6 项移动端真触屏断言：位图尺寸一致、点城池、缩放后命中、点兵不串到邻居、拖放落点等于视觉格、rect 偏移后仍命中）、81 单测、静态自检全绿。
另在烟测里修了一个测试夹具问题：授简层是异步 `start()` 的，过早 `hide()` 会被随后的 `render()` 重新显示，简卡会吃掉地图点击 —— 现在等简卡出现再跳过。

**没动**：工笔画风（`gongbi.js`）、UI 墨底印玺皮、24×16 逻辑网格与部署存档、城内真实战斗结算。

## v0.6.0：一笔山脊实验 —— 实拍不成立，已退回界画

**结论：不成立，按预案整体退回。** 只挑了 `RIDGES[0]` 嵩山一条折线做实验：

`terrain.js` / `map-data.js` / 存档 / 策略层一行没动。

实拍（1440×900）：

| 视角 | 界画 vs 一笔 | 观感 |
| --- | --- | --- |
| 默认全图 | 差异仅 **17 px** | 整幅的气没变：嵩山主脊在初始视口之外 |
| 镜头推近主脊 | 7570 px，集中在 x131–455 / y61–846 | 那一笔读成**划痕**而非山脊：墨色比皴暗、与等宽等浓的格状山形异质，周围皴法仍统治画面 |

所以没有推广到河与官道，也没有动配色。失败实验在 v0.7.0 起已整体清除；当时 `?brush=on` 曾作 A/B 复核开关。（烟测对离屏主脊带做 40×40 像素校验和：开/关不同、关掉后与界画完全一致）。

要让它成立，得先解决「笔与皴的明度与朝向关系」：笔要读成受光的脊而不是沟，
两侧皴法得顺着笔势组织 —— 那已经不是「最小一步」了，等这个方向定了再动。

**收尾暂存**：整份 UI 配色清单仍未落地（`styles/main.css` 保持原样），留作最后一遍收尾。

## v0.5.0：行台授简 / 审美收尾（留白与读图）

### 1. 新手引导：行台授简十二简

不是一张静态玩法面板，是**跟着真实动作走的十二枚简**：受檄入局 → 观军历 → 读纪事 → 观舆图 → 相地块 → 下军令 → 推军历 → 在途军情 → 入城布阵 → 调兵与单兵 → 两端并行 → 合卷自行。每简有叙事、史注引文、聚焦目标与一句「去做什么」。

- **事件驱动**：第三简等 `tab:story`、第四简等 `mapPanned`、第五简等 `tileSelected`、第六简等 `orderIssued`、第七简等 `turnAdvanced`、第八简等 `orderPanelOpened`、第九简等 `battleOpened`、第十一简等 `battleClosed`。事件只认当前那一简，纯阅读简不吃事件，乱点不会跳简。
- **不锁死**：遮罩与高亮框 `pointer-events:none`，只有简卡吃指针——被引导的「拖地图 / 点地块」是真的能操作。每一步也都能手动「下一简」，不做强制卡关。四条退路：上一简 / 跳过 / Esc 暂收 / 合卷。
- **不盖 Tab**：简卡定位避开底栏（沿用 v0.4 的 `#screen{bottom:58px}`），引导期间 11 个入口照常可点。
- **边界**：引导是**本机界面状态**，独立 `localStorage` key，不进 `campaign state`、不进 `commandLog`、不进 `stateFingerprint`、不进军令帖——导入对方存档不会继承对方看过几简，联机重放也不受污染。刷新后按进度续播；已完成/已跳过不重播；系统页「重看行台授简」可从头再来。
- 状态机 `src/tutorial.js` 是纯逻辑（可序列化、可重放），DOM 只在 `src/tutorial-ui.js`；`config/tutorial.json` 存全部文案，改字不碰代码。

### 2. 审美：只做减法后的「撑住」与「层级」

| 评审原话 | 做法 |

## v0.4.0：年号军历 / 官渡章回 / 联机地基 / 审美收尾

### 1. 不再说「第几旬」

`src/calendar.js` 把内部 `turn`（1 旬 = 10 日）映射成 **建安五年 正月初一 → 十一 → 廿一 → 二月初一**，3 旬进一月，12 月进一年，带干支（庚辰）与孟春/仲夏等时令。顶栏、行军抵达、战报、斥候回报、存档摘要、结算全部改用年号月日；`arrivalLabel()` 给「四月十一 抵达」这类短标签。逻辑层、`A*`、双时钟一行没动——只是显示层换了套历法。

### 2. 剧情线，不再三选一

- **身份由剧情给定**：司空府参军事，奉命领行台文书。主菜单是**序章卷轴**（檄文、史注、朱印、开局侧重二选一：屯田积谷 / 遣斥候北探），不是势力下拉框。
- **任务线并入纪事**：底部 Tab 的「任务」合为「纪事」，一页里同时有章回叙事、史注、本回军务进度、行台议决、已过章回回看、日常陈情。目标与任务共用同一套 `state` 派生，不是写死进度。
- **月份锁**：`minTurn` 绑定史实时序，目标提前做完也要待时至二月才能入「黎阳压河」。推进时发犒赏、应用抉择、写入入场史实事件（白马被围 / 解围、颜良文丑阵亡、官渡相持、许攸夜奔、乌巢焚粮）与私信（刘延告急、荀攸论分势、荀彧答曹公书、许攸献计、露布报捷）。
- **净行动口径**：开局已有 9 城 468 格，绝对数会白送进度。`state.storyBaseline` 记开局基线，`claim` 用实际占据事件、`citiesGain` 用净得敌城数。

### 3. 无预算能做联机吗

**能做的是地基与异步对演，做不了跨设备实时房间。** `src/sync.js` 不引用任何后端、账号、墙钟、网络库：

| 已落地 | 边界 |
| --- | --- |
| 带 `seq / turn / actor / rngBefore / rngAfter` 的**命令日志**（所有状态变更都经 `applyEntry` 记账，含章回推进与界面动作） | 逻辑时间只有 `turn`，没有 `Date.now()`，两端不会因本地时钟分叉 |
| `stateFingerprint()` / `hashState()` 只取玩法字段，紧凑 16 位指纹 | 地形按 seed 重建，只比差异格 |
| `verifyReplay()` 双路径对演：A 直接建局 / B 存档往返，逐步比对指纹 | 单测里 12 步全一致；人为分叉能定位到具体步号 |
| `createLoopbackTransport()` / `createBroadcastTransport()`（同浏览器多标签，Node 下 `unref()` 不挂事件循环） | 三种 actor 态 `human / ai / remote` 已预留，命令一律带 actor |
| **军令帖**：`encodeTicket/decodeTicket` 把存档 + 命令日志尾压成 base64url 口令，复制给对方即可接着这局下令，play-by-email | 系统页可导出 / 导入 / 校验重放 / 看边界 |

### 3. 手机：状态属于这局，不属于这个页面

## v0.2.0：清晰度 / 指令层 / 城池布阵

### 0. 两个界面，职责严格分开

| | 大地图 (`map-render.js`) | 城池小地图 (`city-view.js`) |
| --- | --- | --- |
| 视口 | 可拖动、可缩放、`全图`、右下角缩略导航 | **固定视口，一屏放下 24×16 城内网格；不拖动、不缩放** |
| 交互 | 只**下指令**（12 类，全部带 `arriveTurn`） | 只**调兵**：拖拽把单位在「城外大营 ↔ 城内」之间部署；圆框选 + 二次拖拽定方向；单击单兵接管 |
| 绘制 | 地貌离屏预渲染，信息层屏幕空间 | 全部主画布按屏幕像素绘制 |

### 清晰度为先

`tilePx` 12 → **24**，离屏位图 `3456×2592`。更关键的是分层：**城名、山水注记、关隘名、土地等级、图廓、比例尺全部移到屏幕空间绘制**，字号/线宽按 `1/camera.scale` 换算，永远是固定物理像素，不随缩放被插值糊掉。山形/树冠/河纹/官道线宽与对比度同步提高；接近 1:1 才用高质量插值，缩到很小时用最近邻保住细线。

### 大地图不止「占领地块」

`claim / march / scout / develop / buildFort / transfer / garrison / withdraw / recruit / fireDirectional / stratagem / reinforce` 共 12 类，配置与指令层一一接线：

- **屯田**：己方地块 `level+1`，重算四资源产出
- **筑垒**：己方地块生成垒寨、通行代价下降
- **侦察**：写 `intel` 情报（守军/城防/士气/归属），不改兵力、不开战
- **调动 / 驻守**：只对己方城；**出征 / 增援**：只对敌方城
- **撤兵**：从敌城大营收兵回出发城；**撤令**：退还尚未出发的兵员与已扣资源
- 资源池是**可花费的累积库存**，与「每旬流量」分离（`state.resources` vs `state.yield`）
- 「在途军情」面板列出所有命令、预计抵达旬、路径格数，可逐条撤令

### 己方在城内，敌方在城外扎营

`campaign.forces[cityId] = { inside, camp }`，每个元素是独立实体（id / 兵种 / 阵营 / hp / 格位 / 人数 / 选中态）：

- 开局各城守军展开为**城内**实体
- 抵达**己方**城 → 新部队进 `inside`（布防）
- 抵达**敌方**城 → 新部队进 `camp`（**城外扎营**），城内是守军
- 小地图把 `camp` 里的兵**拖进城里 = 派人进去打**，拖回 `camp` = 撤出；这就是「先打着、后续投入、中途退出」的落点

### 两端并行的架构级约束

退出子界面拍快照时**深拷贝 `forces`**；恢复时按 **unit id 合并**，不是无条件覆盖 —— 否则离开期间策略层并行抵达的援军会被旧快照冲掉，直接违反「两端并行」。同时把 `createCityView` 改成**单例 + `AbortController` 一次性绑定**，切换城池只换 `getCityId()`，避免重复监听导致一次拖拽触发多次部署。

## v0.1.0 做了什么

### 1. 足够复杂的真实地块地图

不再是 12 个城点连几条直线，而是 **15552 个格子**，每格有 `type / base / level / yield / cost / owner / cityId`。

- **真实地理骨架**：汉末黄河故道（荥阳北→延津→白马→黎阳）、颍水/汝水/鸿沟/淇水/荡水、圃田泽/荥泽/大野泽、嵩山—箕山—太行—历山、虎牢关/轘辕关与四处津渡；十二座史实名城（许都、邺、汝南、陈留、黎阳、濮阳、阳翟、谯县、中牟、白马、延津、官渡）。
- **分层程序化地形**：确定性 fbm 高程场叠加山脊抬升与河谷压低，再刷泽薮、水系、城郭、官道、关隘、津渡。道路沿 `via` 折线蜿蜒，不是两点直线。
- **画风**：底纹 → 地貌色块 → 三角山形与等高线 → 树冠/田埂/芦苇 → 河面波纹与河岸 → 官道双线车辙 → 城郭垛口、角楼、城门洞、旗纛 → 竖排城名与山水注记。刻意不做「圆圈中间写汉字」。全离屏预渲染一次，主画布只做视口 blit + 动态层。
- **零位图、零墙钟、零 `Math.random`**：同一 seed 生成结果逐字节一致（单测守这条）。

### 2. 率土之滨式的地块规则

| 机制 | 实现 |
| --- | --- |
| 土地等级 1–9 | 按高程、林地、距城加成推导，缩放足够时显示角标 |
| 四资源时产 | 木/石/铁/粮按 `base × level` 逐格累加到势力资源池 |
| 连地铺路 | 目标格 8 邻域内必须有己方领地才能出征，`claim` 命令逐格推进 |
| 行军需要时间 | **A\* 8 向寻路**（禁止斜穿两个障碍角），累计 `tile.cost` 折算 `arriveTurn`；山地/大河不可通行，关隘与津渡是唯一通道，官道代价 0.55 最快 |
| 命令是计划任务 | `Order { arriveTurn, atSec, path }` 存进在途队列，绝不即时生效；到达时结算 |
| 时间驱动 | 全局累计模拟秒 `turn × secPerTurn`；策略层、战斗层、邮箱共用这一个基准 |

自检实测：`许都 → 邺` 78 格 / 88.8 代价 / 5 旬，每旬约 18.9 格；十二城两两 A\* 全连通（城门被汝水/山脉封死时自动刷短堤道接线）。

### 3. 三国策式的策略层

- **内政/回合**：1 回合 = 1 旬（建安五年二月上旬起），人口增长、粮草收支、募兵、城防修复、疲劳恢复。
- **隐藏属性**：士气 / 疲劳 / 粮草 / 警觉 / 阵型完整度都不直接显示，只通过溃散、被擒、征兵上限、行军速度间接生效。对齐三国策「士气决定行动顺序与攻防倍率、粮尽则士气掉」的思路（本轮先落漂移与围城惩罚）。
- **军师是辅助**：`junshi` 零伤害、无投射物，只有鼓舞/疑兵/火攻计策槽。**没有巫师、巨人、矿工、法球、召唤、眩晕**——三国背景里这些东西违和。
- **兵种**：刀盾、长枪、弓弩、床弩、抛石机、重甲步、军师。所有 `projectile != null` 的远程单位都能吃「圆框选 → 二次拖拽定方向」的齐射指令，不只弓手。
- **单方但可任选**：开局选曹操 / 袁绍 / 刘备，其余势力由 AI 每两旬决策（优先铺路，其次出征），确定性 RNG。

### 4. 两端并行，不是冻结

这是最容易写错的一条。战斗层**不是一直空转的后台进程**：

```
enter(snapshot, nowTurn) → 用同一个 advanceBattleStep() 固定步长空跑到 nowTurn
                         → 接上 rAF 实时循环
leave()                 → 拍 BattleSnapshot { sec, campaignTurn, rngSnapshot,
                                              pendingOrders, morale, cityWall, ... }
                         → 战斗层完全停跑；策略日历照常走
```

- 「隔一个月再点进去」**不另写解析结算公式**，而是拿同一份纯逻辑以 1/60 秒无渲染空跑几千步（毫秒级）。因此「一直盯着打」和「离开再回来」结果**必然一致**——单测逐字段比对 `sec / stepsRun / morale / cityWall / pendingOrders`。
- 邮箱事件带 `atSec` 时间戳，按**整数步索引**回放，不是月末一次性倾倒。既避免 `1/60` 累加 480 次后的浮点漏判，也避免放宽容差导致的重复消费。
- `rngSnapshot` 可序列化，快进后随机序列不分叉。
- 终局回写以 `battleEndTurn` 为准，**绝不回退到开战那一回合**；城池易主时同步栅格归属，地图颜色与策略状态不分叉。

### 5. 画风与交互

- 拖动 >140px 平移地图、短拖画圆框选、单击看格详情、双指/滚轮/`＋−` 缩放、回中。
- 每个能进的层都有醒目 `×`：`Esc` 分级 `玩法 → 战场 → 信息卡`。窄屏信息卡变底部抽屉。
- 顶栏实时显示日期、势力、四资源与已占领地块数；信息卡给地形、等级、四资源时产、通行代价、归属。

## 已知限制（下一轮接）

- **城池小地图目前是布阵层**：有网格、独立单位、拖拽部署、框选/定向指令、单兵接管标记；但**没有真实战斗结算**（伤害、投射物飞行、士气溃散、主帅被擒判定都还没接）。快照只保留部署与时钟，不推进伤亡。
- **界面数据是展示层**：设施等级、武将、战法、部队编成、任务、邮件已可交互且随存档持久化，但设施对行军速度 / 兵种克制 / 战损的实际加成、武将五维对行军与胜负的影响、战法在战斗层的消费、同盟捐献加成，都还没接进 `campaign` / `battle-session` 的数值口径。
- **双指捏合已在装配层实现**，但真机多点触控与惯性 fling 未做（无真机环境）；镜头变换仍是瞬跳，没有缓动。
- 章回的史实事件是**入场触发**，不是逐帧战斗推演；城内真实战斗结算（伤害、投射物、士气溃散、擒主帅）仍未接。抉择的 effect 已作用于城防/士气/情报/资源，但设施等级、武将五维、战法还没接进行军速度与战损数值。
- 存档是**本机 localStorage 单档** + 军令帖手动交换，没有账号、云同步、多档位与服务器权威时间；跨设备实时房间属需常驻服务的范围，见上文。
- 引导的「事件驱动」依赖装配层在对应动作处发出 `tutNotify`；若以后新增动作想让引导跟着走，需同时改 `config/tutorial.json` 的 `await` 与 `main.js` 的接线，静态自检会核对两者一一对应。
- 旧 `stick-war` 的横版战斗尚未作为子模块接入；接入时只保留伤害/状态/箭矢/投射物/确定性 RNG，坐标要从一维 `x` 换成 `Vec2`，胜负条件从「雕像血量」换成城门/府衙 + 主帅状态机，矿工与宝石整条不挂载。
- 武将只有「某城守将」占位，暂无五维（统率/武力/智力/政治/忠诚）、录用/解雇、带兵上限与俘虏招降。
- 定向齐射指令已进邮箱，但战斗层尚未消费它；近战单位收到同一指令时的「突击」也只是状态标记。
- 没有合击、兵种相克矩阵、训练度分段、米仓补给范围、阵法（赤火/玄水/八阵图）——这些是三国策里士气系统的核心，留到策略层第二轮。
- 没有同盟、赛季、多人、云存档；`localStorage` 也还没接，快照目前只在内存里。
- 地块产出是「按领地逐格累加」，没有名望上限、领地上限与土地开发计略。
- 战斗服/调度服是本地单进程模拟，没有服务端任务调度与幂等日志。

## 参考口径

率土之滨：225 万格土地与等级产出、连地铺路、行军时间由距离与兵种速度决定、武将兵力兼作 HP 与伤害加成、攻城值削耐久、SLG 服务端按时间队列驱动任务而非玩家即时触发（网易官方「地图玩法」「武将介绍」及 SLG 服务端架构资料）。三国策：内政/战斗两阶段、士气决定行动顺序与攻防、军粮与鼓舞影响士气、军师为辅助、兵种相克与训练度（官网「内政篇」「战争篇」「基础兵法」）。本库取两者的**结构**，不复制数值。
