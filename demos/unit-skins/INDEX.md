## 这轮跟「调色」的区别

- **五套主体画法各写各的**，不是同一图章循环换色：B 是工笔填充、C 是墨块剪影、
  D 是纯线描、E 是分段镂空、F 是反白线笔。
- **将领的姓名 + 五维派生特征真的改变形状**：`helm`（兜鍪尖/平、束发、儒冠）、
  `weapon`（戟/槊、剑、羽扇、弓）、`cape`/`capeCut`、`beard`、`brow`、`scar`、
  `plume`、`bannerShape` 全部落到路径上。第一版 B 的四名将领几乎一个样，实拍
  直接推翻，补了 `helmPts / capePts / weaponStrokes / facePts` 一组共享形制。
- **A 档显示的是游戏里真实看到的位图**，不是拿程序化回退冒充「保存的旧版」。
- **主地图驻军 / 行军队列的简笔也按档重画**，不是只换城内小地图。

## 切换与回退

- 游戏内：**系统 → 单位样式**，六档按钮即时切换，大地图与城池布阵同时换；
  本机界面状态，不进局面 / 存档 / 命令日志 / 状态指纹。
- 对照页：左上角下拉。
- 回退：切回 A 即可。A 档 `drawSoldier` / `drawGeneralPortrait` 与原模块
  **逐命令一致**（`tests/unit-skin.test.mjs` 有硬断言）；整仓回退见 `BACKUP.md`。

## 如实边界（挑的时候一并看）

1. **重绘档会绕开八向位图**：`portrait.js` 加了一道闸门，非 A 档返回 false，
   调用方回退到重绘层。所以 B–F 是**程序化路径**，与 A 的写实位图不是同一
   种素材观感——这是「重绘」的代价，不是 bug。
2. **A 与 B–F 不在同一渲染管线上**，挑的时候请按「要写实位图」还是「要手绘
   笔法」这个方向问题先定，再挑哪一档手绘。
3. **将领立绘本来就是程序化的**（A 档也是），所以将领那一行六档可直接比。
4. **E 皮影最偏离 58° 斜俯视口径**，是平面化戏偶；若要保持俯视写实，别选它。
5. **F 需要深底**，浅绢底上会偏淡；游戏内大地图是墨底，恰好合适。
6. **城郭 / 注记 / 势力层 / 地图底图一律没动**，这轮只管单位。
7. **小程序端不受影响**：`unit-skin.js` / `unit-redraw.js` 是渲染层，不在
   `sync-miniprogram.mjs` 的纯逻辑闭包里；端侧仍是原样。
